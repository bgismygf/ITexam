# 0-4 基本名詞：資料表、列、欄、資料型態 🎯💼

## 資料表（Table）

關聯式資料庫把資料存成一張張**資料表**，長得很像 Excel 的工作表。
以題庫的 `exams` 資料表為例：

```
                ┌─────────── 欄（Column）─────────────┐
                ▼                                      ▼
  ┌─────────┬──────┬───────────┬──────────┬────────────┐
  │ exam_id │ year │ organizer │ category │  subject   │
  ├─────────┼──────┼───────────┼──────────┼────────────┤
  │    1    │ 110  │ 自編範例   │   資訊    │ 計算機原理  │ ← 列（Row）
  │    2    │ 111  │ 自編範例   │   資訊    │ 計算機原理  │ ← 列（Row）
  │    3    │ 112  │ 自編範例   │   資訊    │  網路概論   │ ← 列（Row）
  └─────────┴──────┴───────────┴──────────┴────────────┘
```

- **欄（Column）**：一種屬性，例如「年度」「科目」。每一欄的資料型態固定
- **列（Row）**：一筆完整的資料，例如「110 年的計算機原理考試」
- **值（Value）**：某一列、某一欄交會的那一格

## 🎯 同一個東西，三套名稱（必背）

考試題目會混著用，三套都要認得：

| 日常 / SQL 用語 | 關聯式理論用語（考試常用） | 檔案系統用語 |
|---|---|---|
| 資料表 Table | **關聯 Relation** | 檔案 File |
| 列 Row | **值組 Tuple** | 記錄 Record |
| 欄 Column | **屬性 Attribute** | 欄位 Field |

另外幾個常考名詞：

| 名詞 | 意思 | 用 exams 舉例 |
|---|---|---|
| **分支度 Degree** | 一張表有幾個**欄（屬性）** | exams 有 7 欄 → Degree = 7 |
| **基數 Cardinality** | 一張表有幾個**列（值組）** | exams 有 5 列 → Cardinality = 5 |
| **值域 Domain** | 某個屬性**允許的值的範圍** | answer 的值域是 {A, B, C, D} |
| **綱要 Schema** | 表的**結構**（表名、欄名、型態），不含資料 | `exams(exam_id, year, organizer, ...)` |
| **實例 Instance** | 某個時間點表中**實際的資料** | 目前那 5 筆考試資料 |

💡 **記憶法**：Degree 是「直的」幾欄，Cardinality 是「橫的」幾列。
「Cardinality = 筆數」，Card（卡片）一張一筆。

## 🎯 關聯（資料表）的特性

1. **列沒有順序**：第 1 列和第 3 列對調，還是同一張表
2. **欄沒有順序**：（理論上）欄位前後對調，意義不變
3. **不能有完全重複的列**：每一列都必須能被區分（所以需要「主鍵」，第 6 單元）
4. **每一格只能放一個值**：不能在一格裡放「A, C」兩個答案（這叫**基元值 atomic**，是第一正規化 1NF 的要求）

## 資料型態（Data Type）

每一欄都要指定存什麼類型的資料。SQLite 的型態很簡單：

| SQLite 型態 | 存什麼 | 題庫裡的例子 |
|---|---|---|
| `INTEGER` | 整數 | `year` 年度、`question_no` 題號 |
| `REAL` | 小數 | `score` 配分（1.5、2.5） |
| `TEXT` | 文字 | `subject` 科目、`content` 題目內容 |
| `BLOB` | 二進位資料（圖片、檔案） | （題庫目前沒用到） |
| `NULL` | 空值，代表「沒有資料 / 未知」 | 第 29 題的 `answer` 還沒輸入 |

💼 **其他資料庫的常見型態**（工作會遇到）：

| 用途 | MySQL | SQL Server |
|---|---|---|
| 整數 | `INT`、`BIGINT` | `INT`、`BIGINT` |
| 精確小數（金額一定用這個） | `DECIMAL(10,2)` | `DECIMAL(10,2)` |
| 固定長度文字 | `CHAR(10)` | `CHAR(10)`、`NCHAR(10)` |
| 可變長度文字 | `VARCHAR(100)` | `VARCHAR(100)`、`NVARCHAR(100)`（存中文用 N 開頭） |
| 日期時間 | `DATE`、`DATETIME` | `DATE`、`DATETIME2` |

🎯 **常考**：`CHAR` 和 `VARCHAR` 的差別
- `CHAR(10)`：**固定**佔 10 個字元，不足會補空白。適合長度固定的資料，例如身分證字號
- `VARCHAR(10)`：**最多** 10 個字元，用多少佔多少。適合長度不固定的資料，例如姓名

## NULL 不是 0，也不是空字串

- `NULL` 代表「**沒有值 / 未知**」
- `0` 是一個數字，`''`（空字串）是一段長度為 0 的文字，它們都「有值」
- 例如：第 29 題 `answer` 是 NULL，表示「答案還沒輸入」，不是「答案是空的」

第 1 單元會詳細教怎麼處理 NULL（這是很多人寫錯 SQL 的原因）。

## 小測驗

1. 在關聯式資料庫中，一個關聯（Relation）中值組（Tuple）的個數稱為？
   (A) Degree (B) Cardinality (C) Domain (D) Schema

2. 某資料表有 8 個屬性、120 筆資料，其分支度（Degree）為？
   (A) 8 (B) 120 (C) 128 (D) 960

3. 下列關於關聯的敘述，何者錯誤？
   (A) 值組之間沒有順序 (B) 不允許完全相同的值組
   (C) 一個屬性值可以包含多個值 (D) 每個屬性有其值域

<details>
<summary>看答案</summary>

1. **(B)** Cardinality（基數）＝列數
2. **(A)** Degree（分支度）＝欄數＝8
3. **(C)** 每個屬性值必須是單一的基元值（atomic）
</details>
