# 5-3 限制條件 🎯💼

## 觀念

**限制條件（Constraint）** 是替資料表設定的「規則」，由資料庫自動檢查，
違反規則的資料**會被拒絕寫入**。這是資料庫比 Excel 可靠的主要原因之一。

## 六種限制條件

| 限制 | 作用 | 範例 |
|---|---|---|
| `NOT NULL` | 不可以是 NULL | 題目內容一定要有 |
| `UNIQUE` | 值不可以重複 | 章節名稱不能重複 |
| `PRIMARY KEY` | 主鍵：唯一識別每一列 | `question_id` |
| `FOREIGN KEY` | 外來鍵：值必須存在於另一張表 | `questions.exam_id` 必須是存在的考試 |
| `CHECK` | 自訂條件 | 答案只能是 A～D |
| `DEFAULT` | 沒給值時的預設值 | 作答時間預設為現在 |

## 1. NOT NULL

```sql
title TEXT NOT NULL
```

## 2. UNIQUE

```sql
name TEXT UNIQUE
-- 或多個欄位的組合不能重複：
UNIQUE (exam_id, question_no)     -- 同一份考試的題號不能重複
```

🎯 **UNIQUE 允許 NULL**，而且大部分資料庫允許**多個** NULL（因為 NULL ≠ NULL）。
⚠️ SQL Server 例外：UNIQUE 欄位只能有一個 NULL。

## 3. PRIMARY KEY 主鍵 🎯

```sql
question_id INTEGER PRIMARY KEY
-- 或多個欄位組成的「複合主鍵」：
PRIMARY KEY (question_id, label)
```

🎯 **主鍵的特性（必考）**：
1. **唯一**（不可重複）
2. **不可為 NULL**（實體完整性）
3. 一張表**只能有一個**主鍵（但主鍵可以由多個欄位組成）

可以想成：**PRIMARY KEY = UNIQUE + NOT NULL**，而且一張表只能有一個。

> ⚠️ SQLite 的歷史包袱：非 INTEGER 型態的主鍵允許 NULL，除非另外加 NOT NULL。
> 其他資料庫都不允許。

💼 SQLite 的 `INTEGER PRIMARY KEY` 會**自動編號**：新增時不給值，會自動填入目前最大值 + 1。
其他資料庫的寫法：MySQL `AUTO_INCREMENT`、SQL Server `IDENTITY(1,1)`、PostgreSQL `SERIAL` / `GENERATED AS IDENTITY`。

## 4. FOREIGN KEY 外來鍵 🎯

```sql
exam_id INTEGER REFERENCES exams(exam_id)
-- 或完整寫法：
FOREIGN KEY (exam_id) REFERENCES exams(exam_id)
```

作用：`questions.exam_id` 的值，**必須是 exams 表中存在的 exam_id**（或是 NULL）。
- 新增題目時，exam_id = 999 但沒有第 999 份考試 → **拒絕**
- 刪除還有題目的考試 → **拒絕**（除非設定 CASCADE，5-6 課）

這叫做**參考完整性（Referential Integrity）**。

> ⚠️ SQLite 預設**不檢查**外來鍵，要先執行 `PRAGMA foreign_keys = ON;`。
> DB Browser 預設會幫你開啟（Edit → Preferences → Database → Foreign keys）。

## 5. CHECK

```sql
answer TEXT CHECK (answer IN ('A', 'B', 'C', 'D'))
score  REAL CHECK (score > 0)
```

⚠️ CHECK 條件的結果是 **UNKNOWN（NULL）時會被接受**，只有 FALSE 才拒絕。
所以 `answer` 是 NULL 時，上面的 CHECK 不會擋。要禁止 NULL 請另外加 NOT NULL。

## 6. DEFAULT

```sql
done       INTEGER DEFAULT 0
created_at TEXT DEFAULT (datetime('now', 'localtime'))
```

## 🎯 完整性限制的分類（必考）

| 完整性 | 意思 | 由誰保證 |
|---|---|---|
| **實體完整性**（Entity Integrity） | 主鍵不可為 NULL、不可重複 | PRIMARY KEY |
| **參考完整性**（Referential Integrity） | 外來鍵的值必須參照到存在的主鍵，或為 NULL | FOREIGN KEY |
| **值域完整性**（Domain Integrity） | 欄位值必須在允許的範圍內 | 資料型態、CHECK、NOT NULL |

## 替限制條件命名

```sql
CONSTRAINT chk_answer CHECK (answer IN ('A', 'B', 'C', 'D'))
```
💼 命名後，錯誤訊息會顯示限制名稱，比較好除錯，之後也可以用名稱刪除限制。

## 小測驗

1. 關於主鍵的敘述，何者錯誤？
   (A) 不可重複 (B) 不可為 NULL (C) 一個資料表可以有多個主鍵 (D) 可以由多個欄位組成

2. 「外來鍵的值必須是被參照表中存在的主鍵值，或為 NULL」，這是指？
   (A) 實體完整性 (B) 參考完整性 (C) 值域完整性 (D) 使用者定義完整性

3. 欄位設定 `UNIQUE` 時，下列何者正確？
   (A) 不允許 NULL (B) 一張表只能有一個 UNIQUE 欄位
   (C) 值不可重複 (D) 等同於主鍵

<details>
<summary>看答案</summary>

1. **(C)** 一張表只能有一個主鍵
2. **(B)**
3. **(C)**
</details>
