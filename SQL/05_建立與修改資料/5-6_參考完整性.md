# 5-6 參考完整性與 ON DELETE CASCADE 🎯💼

## 問題

`questions.exam_id` 參照 `exams.exam_id`。如果要**刪除**一份考試，它底下的題目怎麼辦？

- 題目留著 → 題目的 exam_id 指向一份不存在的考試（**孤兒資料**），違反參考完整性
- 所以資料庫預設會**拒絕**刪除還有題目的考試

我們可以設定「被參照的資料刪除或修改時，要怎麼處理」。

## 語法

```sql
FOREIGN KEY (exam_id) REFERENCES exams(exam_id)
    ON DELETE 動作
    ON UPDATE 動作
```

## 🎯 五種動作（必考）

| 動作 | 父表資料被刪除 / 修改時，子表怎麼辦 |
|---|---|
| **NO ACTION**（預設） | **拒絕**（在敘述結束時檢查） |
| **RESTRICT** | **拒絕**（立即檢查） |
| **CASCADE** | **連帶**刪除 / 修改子表資料 |
| **SET NULL** | 子表的外來鍵設成 **NULL** |
| **SET DEFAULT** | 子表的外來鍵設成**預設值** |

- **父表**（被參照的表）：exams
- **子表**（有外來鍵的表）：questions

### 例子

```
exams（父）            questions（子）
exam_id = 1   ◀─────   question 1, 2, 3 ... (exam_id = 1)
```

刪除 exam_id = 1 時：
| 設定 | 結果 |
|---|---|
| NO ACTION / RESTRICT | 錯誤，刪除失敗 |
| CASCADE | 考試 1 被刪除，**第 1～6 題也一起被刪除** |
| SET NULL | 考試 1 被刪除，第 1～6 題的 exam_id 變成 NULL |

## 💼 怎麼選擇

| 情境 | 建議 | 原因 |
|---|---|---|
| 子表資料**離開父表就沒有意義** | CASCADE | 刪除訂單時，訂單明細也要刪 |
| 子表資料**需要保留** | RESTRICT / NO ACTION | 有訂單的客戶不能被刪除 |
| 關聯是**可有可無**的 | SET NULL | 員工離職時，他負責的案件改成「未指派」 |

⚠️ **CASCADE 要小心**：一個 DELETE 可能連鎖刪掉好幾張表的大量資料。
💼 很多公司的實務做法是**不真的刪除資料**，而是加一個 `is_deleted` 欄位標記為已刪除（稱為**軟刪除 soft delete**）。
