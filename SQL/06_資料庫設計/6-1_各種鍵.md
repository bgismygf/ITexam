# 6-1 超鍵、候選鍵、主鍵、外來鍵 🎯

> 這是資料庫理論的基礎，後面的正規化會一直用到，**必考**。

## 用一個例子說明

學生資料表 `student`：

| 學號 | 身分證字號 | 姓名 | email | 系所 |
|---|---|---|---|---|
| S001 | A123456789 | 王小明 | ming@school.edu | 資工 |
| S002 | B234567890 | 李小華 | hua@school.edu | 電機 |
| S003 | C345678901 | 王小明 | ming2@school.edu | 資工 |

（注意：有兩個人都叫王小明）

## 1. 超鍵（Super Key）

**能唯一識別每一列的「一個或多個屬性的組合」**。

- {學號} ✅
- {身分證字號} ✅
- {email} ✅
- {學號, 姓名} ✅（學號已經能識別了，多加姓名還是能識別）
- {學號, 身分證字號, 姓名, email, 系所} ✅（全部屬性一定是超鍵）
- {姓名} ❌（有兩個王小明）
- {姓名, 系所} ❌（兩個都是資工的王小明）

超鍵可以包含「多餘」的屬性。

## 2. 候選鍵（Candidate Key）

**「最小的」超鍵**：拿掉任何一個屬性，就不再是超鍵。

- {學號} ✅ 候選鍵
- {身分證字號} ✅ 候選鍵
- {email} ✅ 候選鍵
- {學號, 姓名} ❌ 不是候選鍵（拿掉姓名，{學號} 仍能識別，所以「不是最小」）

🎯 候選鍵的兩個條件：
1. **唯一性（Uniqueness）**：能唯一識別每一列
2. **最小性（Minimality / Irreducibility）**：沒有多餘的屬性

一張表可以有**多個**候選鍵。

## 3. 主鍵（Primary Key）

**從候選鍵中「選一個」作為主要的識別方式**。

- 選 {學號} 當主鍵
- 一張表**只能有一個**主鍵
- 主鍵**不可為 NULL**、不可重複（實體完整性）

## 4. 替代鍵（Alternate Key）

**沒被選為主鍵的其他候選鍵**。

- {身分證字號}、{email} 是替代鍵
- 💼 實務上通常替它們加上 `UNIQUE` 限制

## 5. 外來鍵（Foreign Key）

**一張表中的屬性，參照到另一張表（或同一張表）的主鍵**。

```
選課表 enrollment                     學生表 student
┌──────┬──────┬──────┐                ┌──────┬────────┐
│ 學號  │ 課號  │ 成績 │                │ 學號  │ 姓名   │
├──────┼──────┼──────┤                ├──────┼────────┤
│ S001 │ C01  │  85  │  ─── 參照 ──▶   │ S001 │ 王小明 │
└──────┴──────┴──────┘                └──────┴────────┘
  ↑ 外來鍵                              ↑ 主鍵
```

- 外來鍵的值必須存在於被參照的表，**或為 NULL**（參考完整性）
- 外來鍵**可以重複**（一個學生可以選很多課）
- 外來鍵可以參照**同一張表**（例如員工表的主管編號，3-5 課的 Self Join）

## 6. 其他名詞

| 名詞 | 意思 | 例子 |
|---|---|---|
| **複合鍵**（Composite Key） | 由**兩個以上**屬性組成的鍵 | 選課表的 {學號, 課號} |
| **主要屬性**（Prime Attribute） | 屬於**任何一個**候選鍵的屬性 | 學號、身分證字號、email |
| **非主要屬性**（Non-prime Attribute） | 不屬於任何候選鍵的屬性 | 姓名、系所 |
| **自然鍵**（Natural Key） | 資料本身就有意義的鍵 | 身分證字號 |
| **代理鍵**（Surrogate Key） | 人為產生、沒有業務意義的編號 | 自動編號的 id |

💼 **自然鍵 vs 代理鍵**：實務上大多用**代理鍵**當主鍵（例如自動編號），因為自然鍵可能會變
（例如身分證字號可能更改、email 會換），再用 UNIQUE 限制自然鍵不可重複。

「主要屬性 / 非主要屬性」在 6-6 課的正規化會用到，一定要分清楚。

## 🎯 關係整理

```
┌─────────────── 超鍵 ────────────────┐
│                                     │
│   ┌─────── 候選鍵（最小超鍵） ───────┐ │
│   │                               │ │
│   │  ┌── 主鍵 ──┐  ┌── 替代鍵 ──┐  │ │
│   │  │  （選一個）│  │  （其他的） │  │ │
│   │  └──────────┘  └───────────┘  │ │
│   └───────────────────────────────┘ │
└─────────────────────────────────────┘
```

- 主鍵 ⊂ 候選鍵 ⊂ 超鍵
- 每個候選鍵都是超鍵，但超鍵不一定是候選鍵

## 小測驗

1. 關聯 R(A, B, C, D)，已知 {A} 和 {B, C} 都是候選鍵。下列何者「不是」超鍵？
   (A) {A, D} (B) {B, C, D} (C) {B, D} (D) {A, B, C, D}

2. 承上題，非主要屬性為？
   (A) A (B) B (C) C (D) D

3. 關於候選鍵，下列敘述何者錯誤？
   (A) 一個關聯可以有多個候選鍵
   (B) 候選鍵必須滿足最小性
   (C) 候選鍵中的屬性可以是多餘的
   (D) 主鍵是從候選鍵中選出的

<details>
<summary>看答案</summary>

1. **(C)**。{B, D} 不包含任何候選鍵（缺 C，也沒有 A）
2. **(D)**。A、B、C 都屬於某個候選鍵
3. **(C)**。那是超鍵的特性
</details>
