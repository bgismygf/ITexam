# 6-2 ER 模型 🎯💼

> 本課只有觀念，沒有練習檔。

## 觀念

**ER 模型（Entity-Relationship Model，實體關係模型）** 是設計資料庫時用的「藍圖」，
由 Peter Chen（陳品山）在 1976 年提出。

設計資料庫的流程：
```
需求分析 → 概念設計（畫 ER 圖） → 邏輯設計（轉成資料表） → 實體設計（索引、儲存）
                  ↑ 本課                    ↑ 下一課
```

## 三個基本元素

| 元素 | 意思 | 例子 | Chen 符號 |
|---|---|---|---|
| **實體**（Entity） | 要記錄的「東西」 | 學生、課程、考試 | **矩形** ▭ |
| **屬性**（Attribute） | 實體的特徵 | 學號、姓名 | **橢圓** ⬭ |
| **關係**（Relationship） | 實體之間的關聯 | 學生「選修」課程 | **菱形** ◇ |

## 屬性的種類 🎯

| 種類 | 意思 | 例子 | Chen 符號 |
|---|---|---|---|
| **鍵屬性**（Key） | 唯一識別實體 | 學號 | 橢圓，名稱**加底線** |
| **簡單屬性**（Simple） | 不可再分割 | 性別 | 橢圓 |
| **複合屬性**（Composite） | 可以再分成小屬性 | 地址 = 縣市 + 區 + 路名 | 橢圓下面再接橢圓 |
| **單值屬性**（Single-valued） | 只有一個值 | 生日 | 橢圓 |
| **多值屬性**（Multivalued） | 可以有多個值 | 電話（可能有好幾支） | **雙線橢圓** |
| **衍生屬性**（Derived） | 可以從其他屬性算出來 | 年齡（由生日算出） | **虛線橢圓** |

## 實體的種類 🎯

| 種類 | 意思 | Chen 符號 |
|---|---|---|
| **強實體**（Strong Entity） | 有自己的鍵，可以獨立存在 | 矩形 |
| **弱實體**（Weak Entity） | **沒有自己完整的鍵**，必須依附在強實體上才能識別 | **雙線矩形** |

弱實體的例子：「員工的眷屬」。眷屬只有姓名，不同員工的眷屬可能同名，
必須搭配「員工編號＋眷屬姓名」才能識別。
- 弱實體自己的部分鍵稱為**部分鍵（Partial Key）**，用**虛線底線**表示
- 連接弱實體和強實體的關係稱為**識別關係（Identifying Relationship）**，用**雙線菱形**表示

## 關係的基數（Cardinality）🎯

| 基數 | 意思 | 例子 |
|---|---|---|
| **1 : 1** | 一對一 | 一個人 ↔ 一本護照 |
| **1 : N** | 一對多 | 一份考試 → 多道題目；一道題目只屬於一份考試 |
| **M : N** | 多對多 | 一道題目可以屬於多個章節；一個章節有多道題目 |

**判斷方法**：從兩個方向各問一次
- 一份考試有幾道題目？→ **多**
- 一道題目屬於幾份考試？→ **一**
- 所以考試 : 題目 = **1 : N**

## 參與限制（Participation）🎯

| 種類 | 意思 | Chen 符號 |
|---|---|---|
| **完全參與**（Total） | 每個實體**都必須**參與這個關係 | **雙線**連接 |
| **部分參與**（Partial） | 實體**可以不**參與 | 單線連接 |

例：每道題目**都必須**屬於某份考試（完全參與）；但一份考試可以暫時沒有題目（部分參與）。

## 題庫的 ER 圖（Chen 表示法，簡化版）

```
  (year)  (subject)                 (content)  (score)
      \   /                              \     /
   ┌─────────┐       ◇──────◇       ┌───────────┐       ◇──────◇       ┌────────┐
   │  考試    │──1───◇ 包含 ◇───N═══│   題目     │──M───◇ 屬於 ◇───N───│  章節   │
   └─────────┘       ◇──────◇       └───────────┘       ◇──────◇       └────────┘
       |                                 ║  |                              |
   (exam_id)                             ║ (question_id)                (name)
    底線                                  ║   底線
                                    ◇◇◇◇◇◇◇◇◇◇
                                    ◇ 擁有 ◇（識別關係）
                                    ◇◇◇◇◇◇◇◇◇◇
                                         ║ N
                                   ╔═══════════╗
                                   ║   選項     ║  ← 弱實體（依附在題目上）
                                   ╚═══════════╝
                                         |
                                     (label) 虛線底線（部分鍵）
```

說明：
- 考試 : 題目 = **1 : N**，題目那邊是**完全參與**（雙線）
- 題目 : 章節 = **M : N**
- 選項是**弱實體**：選項 A 必須搭配「哪一題」才能識別，部分鍵是 label

## 💼 其他表示法：鴉爪表示法（Crow's Foot）

工作上的設計工具（例如 MySQL Workbench、draw.io、dbdiagram.io）多半用**鴉爪表示法**：

```
考試 ||────────o< 題目          符號：
                                  ||  = 一個（而且必須）
                                  o|  = 零或一個
                                  <   = 多個（鴉爪）
                                  o<  = 零或多個
```

考試以 Chen 表示法為主，工作上鴉爪表示法比較常見，兩種都要看得懂。
