# 6-3 ER 圖轉換成資料表 🎯💼

畫好 ER 圖之後，要依照規則轉換成實際的資料表。

## 🎯 轉換規則（必考）

### 規則 1：強實體 → 一張表

- 實體的**簡單屬性**變成欄位
- **鍵屬性**變成主鍵

```
考試(exam_id, year, subject)  →  CREATE TABLE exams (exam_id PK, year, subject)
```

### 規則 2：複合屬性 → 拆成多個欄位

```
地址 = 縣市 + 區 + 路名   →   city, district, street 三個欄位
```

### 規則 3：多值屬性 → 另外建一張表

```
學生的「電話」（多值）  →  student_phones(student_id FK, phone)
                         主鍵 = (student_id, phone)
```
因為一格只能放一個值（1NF）。

### 規則 4：衍生屬性 → 通常不存

年齡可以由生日算出來，查詢時再算就好（要存也可以，但要注意資料一致性，見 6-7 課）。

### 規則 5：弱實體 → 一張表，主鍵 = 擁有者主鍵 + 部分鍵

```
選項（弱實體，部分鍵 label）依附在題目上
→ options(question_id FK, label, content)
  主鍵 = (question_id, label)
```

### 規則 6：1 : N 關係 → 在 **N 那一方**加外來鍵

```
考試 1 ── N 題目
→ 在 questions 加上 exam_id（外來鍵，參照 exams）
```

💡 **記法**：外來鍵放在「多」的那邊。
因為一道題目只屬於一份考試，所以題目表放一個 exam_id 就夠了；
反過來在考試表放題目編號，就要放很多個（違反 1NF）。

### 規則 7：1 : 1 關係 → 外來鍵放在**任一方**

- 通常放在**完全參與**的那一方，可以避免 NULL
- 例：員工 1 ── 1 管理 ── 部門。每個部門一定有經理，但不是每個員工都是經理
  → 在**部門表**放 `manager_id`（部門是完全參與）
- 也可以考慮**合併成一張表**（兩邊都是完全參與時）

### 規則 8：M : N 關係 → **建立一張新的關聯表**

```
題目 M ── N 章節
→ question_topics(question_id FK, topic_id FK)
  主鍵 = (question_id, topic_id)
```

- 新表包含**兩邊的主鍵**作為外來鍵，兩者組合成主鍵
- 關係本身的屬性也放在這張表

例：學生 M ── N 課程，關係「選修」有屬性「成績」
```
enrollments(student_id FK, course_id FK, score)
主鍵 = (student_id, course_id)
```

這種表有很多名字：關聯表、交叉表、中介表（junction table、bridge table）。

### 規則 9：N 元關係（三個以上實體）→ 建立新表，包含所有參與實體的主鍵

## 總整理

| ER 元素 | 轉換結果 |
|---|---|
| 強實體 | 一張表 |
| 弱實體 | 一張表，主鍵 = 擁有者主鍵 + 部分鍵 |
| 複合屬性 | 拆成多個欄位 |
| 多值屬性 | 另外一張表 |
| 衍生屬性 | 通常不存 |
| 1 : 1 | 外來鍵放任一邊（優先放完全參與那邊） |
| **1 : N** | **外來鍵放 N 那邊** |
| **M : N** | **新建一張表**，主鍵是兩邊主鍵的組合 |

## 小測驗

1. 「學生」與「社團」為 M:N 關係，轉換成關聯式資料表時，最少需要幾張表？
   (A) 1 (B) 2 (C) 3 (D) 4

2. 「部門」與「員工」為 1:N 關係（一個部門有多位員工），外來鍵應該放在？
   (A) 部門表 (B) 員工表 (C) 另建新表 (D) 兩邊都放

3. 弱實體轉換為資料表時，其主鍵為？
   (A) 部分鍵 (B) 擁有者實體的主鍵 (C) 擁有者實體的主鍵 + 部分鍵 (D) 自動編號

<details>
<summary>看答案</summary>

1. **(C)**。學生、社團、加上一張關聯表
2. **(B)**。外來鍵放 N 那邊
3. **(C)**
</details>
