# 6-9 EER 模型：父型態與子型態 🎯

> 建議讀完 6-2（ER 模型）、6-3（ER 圖轉資料表）之後再讀。
> 國營聯招近年沒考，但**考選部的資料庫應用幾乎每年都考**（高考三級、關務、國安、調查局、警察特考）。

## 觀念：為什麼需要 EER

ER 模型只有實體、屬性、關係，表達不出「**一種東西的特殊種類**」。

例子：公司的**員工**有共同的資料（員編、姓名、到職日），但不同種類的員工還有各自的資料：
- **工程師**：專長程式語言
- **業務**：業績目標
- **秘書**：打字速度

如果全部放在「員工」一個實體，大部分欄位對大部分人都是空的；
如果拆成三個毫無關係的實體，又看不出「他們都是員工」。

**EER 模型（Enhanced／Extended Entity-Relationship Model，擴充實體關係模型）**
在 ER 模型上加入**父型態／子型態**，解決這個問題。

| 名詞 | 意思 | 例子 |
|---|---|---|
| **父型態**（Supertype，超類別 Superclass） | 共同的、一般的實體 | 員工 |
| **子型態**（Subtype，子類別 Subclass） | 父型態的特殊種類 | 工程師、業務、秘書 |

子型態和父型態是「**is-a**」的關係：工程師 **is a** 員工。

## 🎯 屬性繼承（Attribute Inheritance）

**子型態會繼承父型態的所有屬性和關係**，再加上自己特有的屬性。

```
員工（員編、姓名、到職日）           ← 父型態：共同屬性
  ├─ 工程師（程式語言）               ← 子型態：只放特有屬性
  ├─ 業務（業績目標）
  └─ 秘書（打字速度）
```

- 工程師**自動**擁有員編、姓名、到職日，不用再畫一次
- 父型態參與的關係（例如「員工 隸屬 部門」），子型態也自動參與
- 子型態也可以有**自己才有的關係**（例如只有業務才「負責」客戶）

💡 和程式語言的**物件導向繼承**是同一個概念，所以考題常說「考量 OO（物件導向）的 EER 設計」。

## 🎯 兩種發展方式：特殊化與一般化

| 方式 | 方向 | 做法 | 例子 |
|---|---|---|---|
| **特殊化**（Specialization） | **由上而下** | 先有父型態，再找出它的子型態 | 先有「員工」，發現有工程師、業務、秘書三種 |
| **一般化**（Generalization） | **由下而上** | 先有幾個實體，發現共同點後抽出父型態 | 先有「汽車」「機車」「卡車」，抽出共同的「車輛」 |

兩者畫出來的圖一樣，差別只在**設計的思考方向**。

## 🎯 兩個限制（必考）

### 1. 完整性限制（Completeness Constraint）

**父型態的每個實例，是否「必須」屬於某個子型態？**

| 種類 | 意思 | 符號 | 例子 |
|---|---|---|---|
| **完全特殊化**（Total Specialization） | 每個父型態實例**一定**屬於至少一個子型態 | 父型態到圓圈畫**雙線** | 每位病人一定是門診病人或住院病人 |
| **部分特殊化**（Partial Specialization） | 父型態實例**可以不**屬於任何子型態 | **單線** | 員工可以只是一般員工，不是工程師也不是業務 |

### 2. 互斥性限制（Disjointness Constraint）

**父型態的一個實例，能不能「同時」屬於多個子型態？**

| 種類 | 意思 | 符號 | 例子 |
|---|---|---|---|
| **互斥**（Disjoint） | **最多只能**屬於一個子型態 | 圓圈內寫 **d** | 一台車不能同時是汽車和機車 |
| **重疊**（Overlap） | **可以同時**屬於多個子型態 | 圓圈內寫 **o** | 一個人可以同時是學生和員工（工讀生） |

### 四種組合

| | 互斥（d） | 重疊（o） |
|---|---|---|
| **完全**（雙線） | 每人**剛好**屬於 1 個子型態 | 每人屬於 **1 個以上**子型態 |
| **部分**（單線） | 每人屬於 **0 或 1** 個子型態 | 每人屬於 **0 個以上**子型態 |

💡 **記法**：完整性問「**能不能一個都不是**」，互斥性問「**能不能同時是好幾個**」。

## EER 圖的畫法

```
                ┌──────────┐
                │   人員    │  ← 父型態
                └────┬─────┘
                     ║          ← 雙線：完全特殊化（每個人一定是員工或客戶）
                    (o)         ← 圓圈內 o：重疊（可以同時是員工和客戶）
                   /    \
                  ⊂      ⊂      ← 線上的 ⊂ 表示這是子型態
          ┌───────┐    ┌───────┐
          │ 員工   │    │ 客戶   │  ← 子型態
          └───┬───┘    └───────┘
              │         ← 單線：部分特殊化（員工可以三種都不是）
             (d)        ← 圓圈內 d：互斥（只能是其中一種）
           /  |  \
          ⊂   ⊂   ⊂
       行政  技術  顧問
```

- 這張圖就是 **115 年調查局**考題的結構（兩層特殊化），考題問「下列敘述何者正確」，就是在考你看懂符號
- 不同教科書的符號略有差異（Hoffer 的教科書把子型態畫在父型態方框裡面），但雙線 / 單線、d / o 的意思都一樣

### 練習判斷（用上圖）

| 敘述 | 對嗎 | 理由 |
|---|---|---|
| 每位人員必是員工或客戶 | ✅ | 人員 → 雙線（完全） |
| 可能有人員既是員工、也是客戶 | ✅ | 人員 → o（重疊） |
| 可能有人員不是員工、也不是客戶 | ❌ | 完全特殊化，至少要是一種 |
| 每位員工必是行政、技術或顧問 | ❌ | 員工 → 單線（部分） |
| 可能有員工同時是行政和技術人員 | ❌ | 員工 → d（互斥） |
| 可能有員工三種都不是 | ✅ | 部分特殊化 |
| 可能有人員是行政人員、也是客戶 | ✅ | 行政人員是員工，員工和客戶可以重疊 |

## 🎯 子型態鑑別子（Subtype Discriminator）

**用父型態裡的一個屬性，記錄每個實例屬於哪個子型態。**

| 限制 | 鑑別子的形式 | 例子 |
|---|---|---|
| **互斥**（d） | **一個**屬性，存一個值 | `EType` = 'A'（行政）、'T'（技術）、'C'（顧問）；部分特殊化時可以是 NULL 或 'N'（都不是） |
| **重疊**（o） | **多個**是非欄位（旗標），每個子型態一個 | `IsEmployee` = 'Y'/'N'、`IsCustomer` = 'Y'/'N'；完全特殊化時，至少一個是 'Y' |

有了鑑別子，新增一筆父型態資料時，DBMS（或程式）就知道要不要、要在哪個子型態表新增對應的資料。

## 其他名詞（了解即可）

| 名詞 | 意思 |
|---|---|
| **特殊化階層**（Specialization Hierarchy） | 子型態下面還有子型態，例如 人員 → 員工 → 行政人員 |
| **共享子型態**（Shared Subclass）、多重繼承 | 一個子型態有多個父型態，例如「工讀生」同時是學生和員工的子型態 |
| **類別**（Category）／聯集型態（Union Type） | 子型態的父型態是**不同種類**的實體，例如「車主」可能是個人、公司或銀行 |

## 🎯 EER 轉換成資料表

父子型態關係有四種轉換方法（以 員工 → 工程師、業務 為例）：

| 方法 | 做法 | 適用 | 缺點 |
|---|---|---|---|
| **1. 父、子各一張表**（最常用） | 員工(**員編**, 姓名, 到職日, 類別)<br>工程師(**員編**FK, 程式語言)<br>業務(**員編**FK, 業績目標) | **任何情況**都能用 | 查完整資料要 JOIN |
| **2. 只有子型態的表** | 工程師(**員編**, 姓名, 到職日, 程式語言)<br>業務(**員編**, 姓名, 到職日, 業績目標) | 只適用**完全 + 互斥** | 不屬於任何子型態的人沒地方放；重疊時資料會重複 |
| **3. 一張表 + 一個類別欄位** | 員工(**員編**, 姓名, 到職日, 類別, 程式語言, 業績目標) | **互斥** | 很多 NULL |
| **4. 一張表 + 多個旗標欄位** | 員工(**員編**, 姓名, 到職日, 是工程師, 是業務, 程式語言, 業績目標) | **重疊** | 很多 NULL |

方法 1 的重點：
- **子型態表的主鍵 = 父型態的主鍵**，同時也是**外來鍵**（參照父型態）
- 父型態表放**子型態鑑別子**（上例的「類別」）

💡 考試沒指定時，用**方法 1** 最安全，寫出每張表的 PK、FK，並說明鑑別子怎麼存。

## 小測驗

1. 「每位員工一定是正職或約聘其中一種，不能兩者都是」，應使用哪一組限制？
   (A) 完全、互斥 (B) 完全、重疊 (C) 部分、互斥 (D) 部分、重疊

2. 先有「汽車」「機車」兩個實體，再抽出共同的父型態「車輛」，這種方式稱為？
   (A) 特殊化 (B) 一般化 (C) 聚合 (D) 正規化

3. 子型態自動擁有父型態的屬性，這個特性稱為？
   (A) 封裝 (B) 屬性繼承 (C) 多型 (D) 參考完整性

4. 父型態是「人員」，子型態是「學生」「教職員」，且可以同時是學生和教職員。
   子型態鑑別子較適合設計成？
   (A) 一個欄位，存 'S' 或 'E'
   (B) 兩個是非欄位：是否學生、是否教職員
   (C) 不需要鑑別子
   (D) 放在子型態的表中

5. 以「父、子各一張表」轉換 EER 時，子型態表的主鍵應為？
   (A) 自動編號 (B) 父型態的主鍵，同時是外來鍵 (C) 子型態特有屬性 (D) 鑑別子

6. 下列哪一種 EER 轉換方法，**只適用於**完全且互斥的特殊化？
   (A) 父、子各一張表 (B) 只建子型態的表 (C) 一張表加類別欄位 (D) 一張表加多個旗標欄位

2. **(B)** 由下而上
3. **(B)**
4. **(B)**。重疊時要用多個旗標欄位
