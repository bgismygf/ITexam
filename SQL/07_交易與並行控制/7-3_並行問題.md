# 7-3 並行問題：遺失更新、髒讀、不可重複讀、幻讀 🎯

> 本課只有觀念，沒有練習檔（SQLite 一次只允許一個寫入者，很難示範並行問題）。

## 觀念

資料庫通常有**很多人同時使用**。如果多個交易同時讀寫同一筆資料，又沒有適當的控制，
就會發生各種問題。

以下用時間軸說明，**T1、T2 是兩個同時執行的交易**，時間由上往下。

## 🎯 1. 遺失更新（Lost Update）

**兩個交易同時修改同一筆資料，後寫入的覆蓋了先寫入的，先寫入的修改就「遺失」了。**

帳戶餘額原本 1000：

| 時間 | T1（存 500） | T2（領 200） | 資料庫中的餘額 |
|---|---|---|---|
| t1 | 讀取餘額 = 1000 | | 1000 |
| t2 | | 讀取餘額 = 1000 | 1000 |
| t3 | 寫入 1000 + 500 = **1500** | | 1500 |
| t4 | | 寫入 1000 − 200 = **800** | **800** ❌ |

正確結果應該是 1300，但 T1 存的 500 元**不見了**。

## 🎯 2. 髒讀（Dirty Read）

**讀到其他交易「還沒 COMMIT」的資料，而那個交易後來 ROLLBACK 了。**

| 時間 | T1 | T2 | 餘額 |
|---|---|---|---|
| t1 | 把餘額改成 5000（**未提交**） | | 5000（暫時） |
| t2 | | 讀取餘額 = **5000** | |
| t3 | **ROLLBACK**（取消修改） | | 1000 |
| t4 | | 用 5000 做決策（例如核准貸款）❌ | |

T2 讀到的 5000 從來沒有真正存在過，稱為「髒」資料。
也稱為**未提交相依問題（Uncommitted Dependency）**。

## 🎯 3. 不可重複讀（Non-repeatable Read）

**同一個交易中，讀取同一筆資料兩次，結果卻不一樣**（因為中間被別人修改並提交了）。

| 時間 | T1 | T2 | 餘額 |
|---|---|---|---|
| t1 | 讀取餘額 = **1000** | | 1000 |
| t2 | | 把餘額改成 2000，**COMMIT** | 2000 |
| t3 | 再讀一次餘額 = **2000** ❌ | | 2000 |

T1 在同一個交易中，兩次讀到不同的值。

## 🎯 4. 幻讀（Phantom Read）

**同一個交易中，用相同條件查詢兩次，結果的「筆數」不一樣**（因為中間有人新增或刪除了符合條件的資料）。

| 時間 | T1 | T2 |
|---|---|---|
| t1 | `SELECT COUNT(*) FROM 員工 WHERE 部門='資訊'` → **5 人** | |
| t2 | | `INSERT` 一位資訊部員工，**COMMIT** |
| t3 | `SELECT COUNT(*) FROM 員工 WHERE 部門='資訊'` → **6 人** ❌ | |

多出來的那一筆就像「幽靈（phantom）」一樣突然出現。

## 🎯 不可重複讀 vs 幻讀（容易混淆）

| | 不可重複讀 | 幻讀 |
|---|---|---|
| 原因 | 別人 **UPDATE（修改）** 了資料 | 別人 **INSERT / DELETE（新增/刪除）** 了資料 |
| 現象 | 同一筆資料的**值**變了 | 符合條件的資料**筆數**變了 |
| 影響範圍 | 單筆資料 | 一個範圍（多筆） |

## 其他：不一致分析（Inconsistent Analysis）

一個交易在做彙總（例如計算所有帳戶總額），計算到一半時，另一個交易修改了資料，
導致加總結果錯誤。這是不可重複讀的一種延伸。

## 總整理

| 問題 | 一句話 |
|---|---|
| **遺失更新** | 兩個人同時改，一個人的修改被蓋掉 |
| **髒讀** | 讀到別人**還沒提交**、後來被取消的資料 |
| **不可重複讀** | 同一筆資料讀兩次，**值不一樣** |
| **幻讀** | 同樣條件查兩次，**筆數不一樣** |

下一課的**隔離層級**，就是用來決定要防止哪些問題。

## 小測驗

1. 交易 T1 修改資料但尚未提交，T2 讀取了該資料，之後 T1 回復，這種問題稱為？
   (A) 遺失更新 (B) 髒讀 (C) 不可重複讀 (D) 幻讀

2. 交易 T1 兩次執行相同的範圍查詢，第二次查詢多出了 T2 新增的資料，這種問題稱為？
   (A) 遺失更新 (B) 髒讀 (C) 不可重複讀 (D) 幻讀

3. 兩個交易同時讀取同一筆資料並各自修改後寫回，造成其中一個交易的修改消失，這稱為？
   (A) 遺失更新 (B) 髒讀 (C) 不可重複讀 (D) 死結

<details>
<summary>看答案</summary>

1. **(B)**
2. **(D)**
3. **(A)**
</details>
