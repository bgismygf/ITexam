# 7-1 交易：BEGIN、COMMIT、ROLLBACK 🎯💼

## 觀念

**交易（Transaction）** 是「**一組必須全部成功、或全部失敗的操作**」。

### 經典例子：轉帳

A 轉 1000 元給 B，需要兩個步驟：
```sql
UPDATE accounts SET balance = balance - 1000 WHERE id = 'A';   -- 1. A 扣錢
UPDATE accounts SET balance = balance + 1000 WHERE id = 'B';   -- 2. B 加錢
```

如果第 1 步完成後，**系統當機**了：A 的錢扣了，B 卻沒收到，1000 元憑空消失！

解法：把兩步包成一個交易，**要嘛兩步都完成，要嘛都不做**。

## 語法

```sql
BEGIN TRANSACTION;           -- 開始交易（也可以寫 BEGIN 或 START TRANSACTION）

UPDATE accounts SET balance = balance - 1000 WHERE id = 'A';
UPDATE accounts SET balance = balance + 1000 WHERE id = 'B';

COMMIT;                      -- 確認：所有修改永久生效
-- 或
ROLLBACK;                    -- 復原：取消交易中所有修改，回到 BEGIN 之前
```

| 指令 | 作用 |
|---|---|
| `BEGIN` | 開始一個交易 |
| `COMMIT` | **提交**：交易中的修改全部永久生效 |
| `ROLLBACK` | **回復**：交易中的修改全部取消 |
| `SAVEPOINT 名稱` | 在交易中設一個「存檔點」 |
| `ROLLBACK TO 名稱` | 回復到存檔點（之前的修改保留） |
| `RELEASE 名稱` | 移除存檔點 |

這些都屬於 **TCL**（交易控制語言）。

## 💡 類比：玩遊戲存檔

- `BEGIN`：開始一個關卡
- 交易中的操作：在關卡中做的事
- `COMMIT`：過關存檔
- `ROLLBACK`：讀取上次存檔，剛剛做的都不算
- `SAVEPOINT`：關卡中途的檢查點

## 自動提交（Autocommit）

大部分資料庫預設是**自動提交模式**：沒有寫 BEGIN 時，**每一句 SQL 執行完就自動 COMMIT**。

- SQL Server、MySQL、PostgreSQL、SQLite：預設自動提交
- **Oracle**：預設**不**自動提交，DML 要自己 COMMIT（忘記 COMMIT，別人看不到你的修改）

## 交易的狀態 🎯

```
              ┌──────────────┐
  BEGIN ────▶ │   活動中      │
              │  (Active)    │
              └──┬────────┬──┘
     最後一句執行完 │        │ 發生錯誤
                 ▼        ▼
     ┌────────────────┐  ┌──────────────┐
     │  部分提交        │  │   失敗        │
     │(Partially      │  │  (Failed)    │
     │  Committed)    │  └──────┬───────┘
     └───────┬────────┘         │ ROLLBACK
       寫入成功│                 ▼
             ▼          ┌──────────────┐
     ┌──────────────┐   │   中止        │
     │   已提交      │   │  (Aborted)   │
     │ (Committed)  │   └──────────────┘
     └──────────────┘
```

## 💼 DB Browser 的交易行為

DB Browser for SQLite 自己就是用交易在運作：
- 你在 Execute SQL 執行的修改，都暫存在一個交易中
- **Write Changes（Ctrl+S）** = COMMIT
- **Revert Changes** = ROLLBACK

所以在 DB Browser 裡直接寫 `BEGIN TRANSACTION` 可能會出現
「cannot start a transaction within a transaction」的錯誤。
本課練習檔改用 **SAVEPOINT**，在 DB Browser 和其他環境都能執行。

## 💼 工作上的重要原則

1. **修改正式資料前，先開交易**：
   ```sql
   BEGIN;
   UPDATE ... WHERE ...;
   SELECT ...;           -- 檢查結果對不對
   -- 確認沒問題 → COMMIT;   有問題 → ROLLBACK;
   ```
2. **交易要盡量短**：交易進行中會鎖住資料，太長會讓其他人等待（7-5 課）
3. **不要在交易中等使用者輸入**（例如交易開了，等人按確認鍵才 COMMIT）
4. 程式中要處理錯誤：發生例外時一定要 ROLLBACK
