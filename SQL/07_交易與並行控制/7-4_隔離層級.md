# 7-4 隔離層級 🎯💼

> 本課只有觀念，沒有練習檔。

## 觀念

完全隔離（每個交易都像獨自使用資料庫）最安全，但**效能最差**（大家都要排隊）。
所以 SQL 標準定義了 **4 種隔離層級（Isolation Level）**，讓使用者在「**正確性**」和「**效能**」之間取捨。

## 🎯 四種隔離層級（必考）

由低到高：

| 隔離層級 | 髒讀 | 不可重複讀 | 幻讀 | 效能 |
|---|:-:|:-:|:-:|:-:|
| **Read Uncommitted**（讀取未提交） | ⚠️ 可能 | ⚠️ 可能 | ⚠️ 可能 | 最快 |
| **Read Committed**（讀取已提交） | ✅ 防止 | ⚠️ 可能 | ⚠️ 可能 | |
| **Repeatable Read**（可重複讀） | ✅ 防止 | ✅ 防止 | ⚠️ 可能 | |
| **Serializable**（可序列化） | ✅ 防止 | ✅ 防止 | ✅ 防止 | 最慢 |

💡 **記法**：層級越高，防止的問題越多，**每升一級多防一種**：
- Read **Committed** → 只讀已提交的 → 防**髒讀**
- **Repeatable** Read → 可以重複讀 → 再防**不可重複讀**
- **Serializable** → 等同依序執行 → 全部都防（包括**幻讀**）

⚠️ **遺失更新**：Read Uncommitted 以上就不會發生「寫入覆蓋未提交的寫入」，
但「讀取 → 計算 → 寫回」這種模式的遺失更新，在 Read Committed 下仍可能發生，
要靠鎖定（例如 `SELECT ... FOR UPDATE`）或直接寫 `SET balance = balance + 500` 來避免。

## 設定語法

```sql
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;
```

## 💼 各資料庫的預設隔離層級

| 資料庫 | 預設 |
|---|---|
| **SQL Server** | Read Committed |
| **Oracle** | Read Committed |
| **PostgreSQL** | Read Committed |
| **MySQL（InnoDB）** | **Repeatable Read** |
| **SQLite** | Serializable（一次只允許一個寫入者） |

## 💼 實務建議

- **大部分情況用預設值**（Read Committed）就夠了
- **Read Uncommitted** 只用在「不在乎精確」的情況，例如粗略的統計報表。
  SQL Server 常見的 `WITH (NOLOCK)` 就是這個層級，要小心使用
- **Serializable** 用在絕對不能出錯的關鍵操作，但要注意效能和死結
- 處理金錢、庫存時，常用「**樂觀鎖**」：加一個 version 欄位，更新時檢查版本有沒有被別人改過
  ```sql
  UPDATE products SET stock = stock - 1, version = version + 1
  WHERE id = 1 AND version = 5;      -- 影響 0 列 → 被別人改過了，重試
  ```

## 小測驗

1. 下列哪一個隔離層級可以防止幻讀？
   (A) Read Uncommitted (B) Read Committed (C) Repeatable Read (D) Serializable

2. 在 Read Committed 隔離層級下，可能發生下列哪一種問題？
   (A) 髒讀 (B) 不可重複讀 (C) 以上皆是 (D) 以上皆非

3. 下列隔離層級中，並行程度最高（效能最好）的是？
   (A) Read Uncommitted (B) Read Committed (C) Repeatable Read (D) Serializable

<details>
<summary>看答案</summary>

1. **(D)**
2. **(B)**。Read Committed 已經防止髒讀
3. **(A)**
</details>
