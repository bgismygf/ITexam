# 9-4 權限管理：GRANT、REVOKE 🎯💼

> ⚠️ **SQLite 沒有使用者和權限的概念**（它只是一個檔案，誰能讀檔案誰就能讀資料），本課只有講義。
> 範例以 SQL Server、MySQL 為主。

## 觀念

公司的資料庫有很多人在用，每個人能做的事不一樣：
- 工程師：可以查詢和修改資料
- 報表人員：只能查詢
- 一般員工：只能看到自己部門的資料
- 管理員（DBA）：全部都可以

**DCL（資料控制語言）** 就是用來管理這些權限。

## 🎯 GRANT：授予權限

```sql
GRANT 權限 ON 物件 TO 使用者;
```

```sql
GRANT SELECT ON exams TO report_user;                       -- 只能查詢 exams
GRANT SELECT, INSERT, UPDATE ON practice_log TO app_user;   -- 可以查詢、新增、修改
GRANT ALL PRIVILEGES ON questions TO admin_user;            -- 所有權限
GRANT EXECUTE ON sp_answer_question TO app_user;            -- 可以執行預存程序
```

### WITH GRANT OPTION

```sql
GRANT SELECT ON exams TO user_a WITH GRANT OPTION;
```
user_a 除了自己能查詢，還可以**把這個權限再授予別人**。

## 🎯 REVOKE：收回權限

```sql
REVOKE 權限 ON 物件 FROM 使用者;
```

```sql
REVOKE INSERT ON practice_log FROM app_user;
```

### CASCADE 與 RESTRICT

如果 user_a 把權限轉授給 user_b，收回 user_a 的權限時：

| 選項 | 結果 |
|---|---|
| `REVOKE ... CASCADE` | user_b 的權限**也一起收回** |
| `REVOKE ... RESTRICT` | 如果有轉授給別人，**拒絕收回** |

> SQL Server 還有 `DENY`：明確**禁止**某個權限，優先順序高於 GRANT。

## 常見的權限種類

| 權限 | 作用對象 | 意思 |
|---|---|---|
| `SELECT` | 資料表、View | 查詢 |
| `INSERT` | 資料表、View | 新增 |
| `UPDATE` | 資料表、View（可以限定欄位） | 修改 |
| `DELETE` | 資料表、View | 刪除 |
| `EXECUTE` | 預存程序、函數 | 執行 |
| `CREATE TABLE` 等 | 資料庫 | 建立物件 |
| `REFERENCES` | 資料表 | 建立參照它的外來鍵 |

```sql
GRANT UPDATE (answer) ON questions TO editor;   -- 只能修改 answer 欄位
```

## 角色（Role）

一個一個使用者設定權限很麻煩，可以先建立**角色**，把權限給角色，再把使用者加入角色：

```sql
CREATE ROLE reporter;
GRANT SELECT ON exams TO reporter;
GRANT SELECT ON questions TO reporter;

GRANT reporter TO user_a;      -- MySQL / PostgreSQL / Oracle
-- SQL Server：ALTER ROLE reporter ADD MEMBER user_a;
```

新人報到只要加入角色就好，離職時移出角色。

## 🎯 用 View 做細部的權限控制

只想讓人看到**部分欄位**或**部分資料**時，可以建立 View，只授權 View：

```sql
-- 員工表有薪資欄位，不想讓一般人看到
CREATE VIEW v_employee_public AS
SELECT emp_id, name, dept FROM employees;      -- 不含 salary

GRANT SELECT ON v_employee_public TO everyone;   -- 只授權 View，不授權原本的表
```

## 💼 安全原則

| 原則 | 說明 |
|---|---|
| **最小權限原則**（Principle of Least Privilege） | 只給完成工作**必需**的權限，不多給 |
| **應用程式不要用管理員帳號連資料庫** | 萬一程式被攻破（例如 SQL Injection），損害範圍會小很多 |
| **職責分離** | 開發人員不應該有正式環境的修改權限 |
| **定期檢查權限** | 離職、調職的人要即時收回權限 |
| **稽核** | 記錄誰在什麼時候做了什麼（9-3 課的 Trigger、資料庫內建的稽核功能） |

💼 國營事業、政府機關對資安的要求很高（例如**資通安全管理法**），權限管理和稽核紀錄是基本要求。

## 小測驗

1. 要授予使用者 A 查詢 emp 表的權限，並允許 A 將此權限轉授他人，應使用？
   (A) `GRANT SELECT ON emp TO A;`
   (B) `GRANT SELECT ON emp TO A WITH GRANT OPTION;`
   (C) `GRANT SELECT ON emp TO A CASCADE;`
   (D) `REVOKE SELECT ON emp FROM A;`

2. GRANT 和 REVOKE 屬於？
   (A) DDL (B) DML (C) DCL (D) TCL

3. 「只給使用者完成工作所需的最少權限」稱為？
   (A) 職責分離 (B) 最小權限原則 (C) 縱深防禦 (D) 零信任

2. **(C)**
3. **(B)**
