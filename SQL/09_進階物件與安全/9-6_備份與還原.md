# 9-6 備份與還原 💼

## 為什麼要備份

資料可能因為各種原因遺失：
- 硬碟損壞
- 人為錯誤（`DELETE` 忘了寫 WHERE）← **最常見**
- 程式 bug 寫入錯誤資料
- 勒索病毒加密
- 天災（火災、地震）

**沒有備份的資料，等於隨時可能消失的資料。**

## 備份類型（7-6 課複習）

| 類型 | 內容 | 備份速度 | 還原速度 | 還原需要 |
|---|---|---|---|---|
| **完整備份** | 整個資料庫 | 慢 | 快 | 最近一次完整備份 |
| **差異備份** | 上次**完整**備份之後的變動 | 中（越來越慢） | 中 | 完整 + 最近一次差異 |
| **增量備份** | 上次**任何**備份之後的變動 | 快 | 慢 | 完整 + 之後**所有**增量 |
| **交易日誌備份** | Log | 快 | | 可以還原到**任何時間點** |

**常見排程**：每週日完整備份 + 每天差異備份 + 每 15 分鐘交易日誌備份

## 💼 3-2-1 備份原則

- **3** 份資料（1 份正本 + 2 份備份）
- **2** 種不同的儲存媒體（例如硬碟 + 磁帶 / 雲端）
- **1** 份放在**異地**（不同的建築物或城市）

## 💼 兩個重要指標

| 指標 | 意思 | 例子 |
|---|---|---|
| **RPO**（Recovery Point Objective） | 最多可以**遺失多久**的資料 | RPO = 15 分鐘 → 每 15 分鐘至少要有一次備份 |
| **RTO**（Recovery Time Objective） | 故障後多久要**恢復服務** | RTO = 1 小時 → 1 小時內要還原完成 |

## 💼 最重要的一件事：測試還原

**沒有測試過還原的備份，不能算是備份。**

很多公司備份做了好幾年，真正出事時才發現備份檔損壞、不完整、或沒人知道怎麼還原。
要**定期實際演練還原**。

## 各資料庫的備份方式

### SQLite

SQLite 的資料庫就是**一個檔案**，備份最簡單：

| 方法 | 說明 |
|---|---|
| 直接複製 `.db` 檔 | 要確定**沒有程式正在寫入**，否則可能複製到不完整的檔案 |
| `VACUUM INTO '路徑'` | 在使用中也能安全地產生一份備份（SQLite 3.27+） |
| `sqlite3 exam.db .dump > backup.sql` | 匯出成 SQL 文字檔（CREATE + INSERT），可讀、可版本控制 |
| DB Browser：`File → Export → Database to SQL file` | 圖形介面的匯出 |

### SQL Server

```sql
-- 完整備份
BACKUP DATABASE ExamDB TO DISK = 'D:\backup\ExamDB_full.bak';
-- 差異備份
BACKUP DATABASE ExamDB TO DISK = 'D:\backup\ExamDB_diff.bak' WITH DIFFERENTIAL;
-- 交易日誌備份
BACKUP LOG ExamDB TO DISK = 'D:\backup\ExamDB_log.trn';
-- 還原
RESTORE DATABASE ExamDB FROM DISK = 'D:\backup\ExamDB_full.bak';
```

### MySQL

```bash
mysqldump -u root -p ExamDB > ExamDB_backup.sql     # 備份
mysql -u root -p ExamDB < ExamDB_backup.sql         # 還原
```

### PostgreSQL

```bash
pg_dump ExamDB > ExamDB_backup.sql
psql ExamDB < ExamDB_backup.sql
```

## 💼 日常工作的小備份習慣

修改重要資料前，先快速備份要改的資料（5-2 課）：
```sql
CREATE TABLE questions_backup_20261122 AS SELECT * FROM questions;
```
改錯了可以從備份表救回來。確認沒問題後記得刪除備份表。
