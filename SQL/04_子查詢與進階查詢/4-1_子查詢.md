# 4-1 子查詢 🎯💼

## 觀念

**子查詢（Subquery）** 是「放在另一個 SQL 裡面的 SELECT」，用括號包起來。
先算出子查詢的結果，再拿給外層查詢使用。

問題：「找出配分**高於平均**的題目」

如果分兩步：
```sql
SELECT AVG(score) FROM questions;                  -- 1. 先算出平均是 2.0
SELECT * FROM questions WHERE score > 2.0;         -- 2. 再拿 2.0 去查
```

用子查詢一次完成：
```sql
SELECT * FROM questions
WHERE score > (SELECT AVG(score) FROM questions);
```
好處是平均值改變時，不用手動修改數字。

## 子查詢的三種回傳型態

| 型態 | 回傳 | 搭配的運算子 | 例子 |
|---|---|---|---|
| **純量子查詢** | 1 列 1 欄（一個值） | `=`、`>`、`<` 等 | `(SELECT AVG(score) FROM questions)` |
| **多列子查詢** | 多列 1 欄（一串值） | `IN`、`EXISTS`、`ANY`、`ALL` | `(SELECT question_id FROM practice_log)` |
| **表格子查詢** | 多列多欄（一張表） | 放在 `FROM` 後面 | `(SELECT exam_id, COUNT(*) ... GROUP BY ...)` |

⚠️ 用 `=` 時，子查詢**只能回傳一個值**，回傳多個值會出錯（或在 SQLite 只取第一個）。
不確定會回傳幾個值時，用 `IN`。

## 子查詢可以放的位置

### 1. 放在 WHERE（最常見）

```sql
-- 作答過的題目
SELECT * FROM questions
WHERE question_id IN (SELECT question_id FROM practice_log);
```

### 2. 放在 FROM（衍生資料表）

把子查詢的結果當成一張臨時的表：
```sql
SELECT AVG(題數)
FROM (SELECT exam_id, COUNT(*) AS 題數
      FROM questions
      GROUP BY exam_id) AS t;
```
「先算出每份考試的題數，再算這些題數的平均」，這種「彙總之後再彙總」一定要用子查詢。

⚠️ FROM 裡的子查詢**要取別名**（`AS t`），大部分資料庫不取別名會報錯。

### 3. 放在 SELECT（純量子查詢）

```sql
SELECT question_id, score,
       (SELECT AVG(score) FROM questions) AS 平均配分
FROM questions;
```

## 子查詢 vs JOIN

很多查詢兩種都能寫：
```sql
-- 子查詢
SELECT * FROM questions
WHERE exam_id IN (SELECT exam_id FROM exams WHERE year = 113);

-- JOIN
SELECT q.* FROM questions q
JOIN exams e ON q.exam_id = e.exam_id
WHERE e.year = 113;
```

| | 子查詢 | JOIN |
|---|---|---|
| 可讀性 | 邏輯清楚，「先找出 113 年的考試，再找題目」 | 熟悉後也很直覺 |
| 需要顯示另一張表的欄位 | ❌ 不行（只能用來篩選） | ✅ 可以 |
| 效能 | 現代資料庫通常會自動最佳化成差不多 | |

💼 **原則**：需要另一張表的欄位就用 JOIN；只是拿來篩選，兩種都可以，選好讀的。
