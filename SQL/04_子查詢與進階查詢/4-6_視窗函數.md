# 4-6 視窗函數 💼

## 觀念

**GROUP BY** 會把多列「壓縮」成一列；**視窗函數（Window Function）** 則是**保留每一列**，
同時在每一列旁邊加上「跟同組資料比較」的計算結果。

```
GROUP BY exam_id                       視窗函數 OVER (PARTITION BY exam_id)
┌─────────┬─────┐                      ┌────┬─────────┬───────┬──────────┐
│ exam_id │ cnt │                      │ id │ exam_id │ score │ 該考試平均 │
├─────────┼─────┤                      ├────┼─────────┼───────┼──────────┤
│    1    │  6  │                      │ 1  │    1    │  1.5  │   2.0    │
│    2    │  7  │                      │ 2  │    1    │  1.5  │   2.0    │
└─────────┴─────┘                      │ 4  │    1    │  2.5  │   2.0    │
  每組只剩一列                           │ ...│   ...   │  ...  │   ...    │
                                       └────┴─────────┴───────┴──────────┘
                                         每一列都保留
```

工作上做報表、分析資料時**非常常用**，面試也很常考。

## 語法

```sql
函數() OVER (
    PARTITION BY 分組欄位     -- 可省略：省略時整張表是一組
    ORDER BY 排序欄位         -- 可省略：排名、累計類的函數需要
)
```

- `PARTITION BY`：像 GROUP BY 一樣分組，但**不壓縮**列
- `ORDER BY`：決定組內的順序

## 常用的視窗函數

### 1. 排名函數

| 函數 | 同分時 | 範例（分數 100, 90, 90, 80） |
|---|---|---|
| `ROW_NUMBER()` | 不管同分，依序編號 | 1, 2, 3, 4 |
| `RANK()` | 同分同名次，**下一名跳號** | 1, 2, 2, 4 |
| `DENSE_RANK()` | 同分同名次，**下一名不跳號** | 1, 2, 2, 3 |

```sql
SELECT question_id, exam_id, score,
       ROW_NUMBER() OVER (PARTITION BY exam_id ORDER BY score DESC) AS 組內排名
FROM questions;
```

### ⭐ 經典用法：每組取前 N 名

```sql
WITH ranked AS (
    SELECT *, ROW_NUMBER() OVER (PARTITION BY question_id ORDER BY answered_at DESC) AS rn
    FROM practice_log
)
SELECT * FROM ranked WHERE rn = 1;   -- 每題最近一次的作答
```

比 4-3 課的相關子查詢更清楚，效能通常也更好。
⚠️ 視窗函數**不能直接寫在 WHERE 裡**（因為 WHERE 比 SELECT 先執行），要包一層 CTE 或子查詢。

### 2. 彙總函數 + OVER

一般的 `SUM`、`AVG`、`COUNT`、`MAX`、`MIN` 加上 OVER 就變成視窗函數：

```sql
SELECT question_id, exam_id, score,
       AVG(score) OVER (PARTITION BY exam_id) AS 該考試平均,
       SUM(score) OVER (PARTITION BY exam_id) AS 該考試總分
FROM questions;
```

### 3. 累計（Running Total）

OVER 裡加上 ORDER BY，彙總函數就會變成「從第一列累計到目前這一列」：

```sql
SELECT answered_at, is_correct,
       SUM(is_correct) OVER (ORDER BY answered_at) AS 累計答對
FROM practice_log;
```
💼 常用於：累計營業額、累計人數。

### 4. 前後列：LAG / LEAD

| 函數 | 意思 |
|---|---|
| `LAG(欄位, n)` | 往**前** n 列的值（預設 n=1） |
| `LEAD(欄位, n)` | 往**後** n 列的值 |

```sql
SELECT question_id, answered_at, is_correct,
       LAG(is_correct) OVER (PARTITION BY question_id ORDER BY answered_at) AS 上次結果
FROM practice_log;
```
💼 常用於：跟上個月比較的成長率、兩次登入的間隔時間。

## 支援度

SQLite 3.25+、MySQL 8.0+、SQL Server、PostgreSQL、Oracle 都支援。
⚠️ **MySQL 5.7 以下不支援**，部分舊系統仍在使用。
