# 3-4 CROSS JOIN 與笛卡兒積 🎯

## 觀念

**CROSS JOIN（交叉合併）** 會把左表的**每一列**和右表的**每一列**都配對一次，
結果稱為**笛卡兒積（Cartesian Product）**。

```sql
SELECT * FROM 表A CROSS JOIN 表B;
-- 舊式寫法：
SELECT * FROM 表A, 表B;
```

## 圖解

```
表A (2 列)     表B (3 列)          A × B (2 × 3 = 6 列)
┌───┐          ┌───┐              ┌───┬───┐
│ 1 │          │ x │              │ 1 │ x │
│ 2 │          │ y │     ──▶      │ 1 │ y │
└───┘          │ z │              │ 1 │ z │
               └───┘              │ 2 │ x │
                                  │ 2 │ y │
                                  │ 2 │ z │
                                  └───┴───┘
```

## 🎯 計算公式（必考）

若表 A 有 **m 列、p 欄**，表 B 有 **n 列、q 欄**：

| | 結果 |
|---|---|
| 列數（Cardinality） | **m × n** |
| 欄數（Degree） | **p + q** |

例：exams（5 列 7 欄）× topics（7 列 2 欄）→ **35 列、9 欄**

## 🎯 JOIN 和笛卡兒積的關係

從理論上看，**INNER JOIN = 笛卡兒積 + 選擇（篩選）**：

```
A ⋈(條件) B  =  σ(條件)(A × B)
```

也就是先把所有組合列出來，再留下符合 ON 條件的。
（實際上資料庫不會真的這樣算，太慢了，但結果相同）

這也說明了**忘記寫 JOIN 條件**的後果：
```sql
SELECT * FROM questions, exams;   -- 忘了 WHERE 條件
-- 30 × 5 = 150 列，每題都跟每份考試配對，資料全錯
```
兩張 10 萬筆的表忘記條件，就會產生 100 億列，可能讓資料庫當掉。

## 💼 CROSS JOIN 的正當用途

雖然少用，但有些情況正好需要「所有組合」：
- 產生報表的骨架：每個月 × 每個部門，即使某月某部門沒有資料也要顯示一列
- 產生測試資料
- 每個學生 × 每個科目，建立空白成績表
