# 3-1 為什麼要拆成多張表

## 如果全部塞在一張表

假設把考題全部放在一張大表：

| 題目編號 | 年度 | 科目 | 倒扣 | 題目 | 選項A | 選項B | 選項C | 選項D | 答案 | 章節 |
|---|---|---|---|---|---|---|---|---|---|---|
| 1 | 110 | 計算機原理 | 是 | 唯一識別每筆資料的是？ | 外來鍵 | 主鍵 | 索引 | 檢視表 | B | 資料庫 |
| 2 | 110 | 計算機原理 | 是 | 何者屬於 DDL？ | SELECT | INSERT | CREATE | UPDATE | C | 資料庫 |
| 19 | 112 | 網路概論 | 否 | 插入惡意 SQL 的攻擊？ | XSS | DDoS | SQL Injection | 釣魚 | C | 資料庫, 資訊安全 |

看起來很直覺，但問題很多：

| 問題 | 例子 |
|---|---|
| **資料重複** | 「110、計算機原理、是」在同一份考試的每一題都重複出現 |
| **修改異常** | 110 年的倒扣規則記錯了，要改 50 列；漏改一列就前後矛盾 |
| **新增異常** | 想先登記「114 年網路概論」這份考試，但還沒有題目，就沒辦法新增 |
| **刪除異常** | 刪掉某份考試的最後一題，連「這份考試存在過」的資訊也一起不見了 |
| **一格多值** | 第 19 題的章節寫「資料庫, 資訊安全」，很難查詢和統計 |
| **欄位固定** | 有 5 個選項的題目放不下 |

這些問題在第 6 單元「正規化」會正式討論，考試很常考。

## 拆表之後

題庫拆成 6 張表，每張表只描述**一件事**：

```
            exams（考試）
              │ 1
              │
              │ N
          questions（題目）───────────┐
           │ 1          │ 1           │ 1
           │            │             │
           │ N          │ N           │ N
       options      question_topics  practice_log
       （選項）      （題目-章節）     （作答紀錄）
                        │ N
                        │
                        │ 1
                     topics（章節）
```

- 每份考試的資訊只存**一次**（在 exams）
- questions 用 **`exam_id`** 指出「我屬於哪一份考試」
- 一題可以有多個章節，透過 question_topics 對應

這個 `exam_id` 在 questions 表中就叫做**外來鍵（Foreign Key）**，
它參照 exams 表的**主鍵（Primary Key）**。

## 拆表的代價：查詢時要「合併」回來

拆表之後，想看「題目內容＋年度＋科目」，資料分散在兩張表。
這時候就要用 **JOIN** 把表合併起來，這就是本單元的主題。

```sql
SELECT q.content, e.year, e.subject
FROM questions q
JOIN exams e ON q.exam_id = e.exam_id;
```
