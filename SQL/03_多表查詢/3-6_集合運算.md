# 3-6 集合運算：UNION、INTERSECT、EXCEPT 🎯

## 觀念

JOIN 是把表「**左右**接起來」（欄位變多）；
集合運算是把兩個查詢結果「**上下**疊起來」（列數變化）。

```
JOIN（左右）              集合運算（上下）
┌───┐ ┌───┐              ┌───────┐
│ A │+│ B │              │ 查詢1 │
└───┘ └───┘              ├───────┤
                         │ 查詢2 │
                         └───────┘
```

## 四種集合運算

| 運算 | 意思 | 數學符號 | 範例 |
|---|---|---|---|
| `UNION` | 聯集，**去除重複** | ∪ | 作答過**或**屬於資料庫章節的題目 |
| `UNION ALL` | 聯集，**保留重複** | | |
| `INTERSECT` | 交集，兩邊**都有** | ∩ | 作答過**而且**屬於資料庫章節 |
| `EXCEPT` | 差集，在第一個、**不在**第二個 | − | 屬於資料庫章節**但沒**作答過 |

> Oracle 的差集叫 `MINUS`，其他資料庫叫 `EXCEPT`。
> MySQL 8.0.31 之前不支援 INTERSECT 和 EXCEPT。

```
   A        B
 ┌────┐  ┌────┐
 │  ┌─┼──┼─┐  │       UNION     = A 和 B 全部
 │  │ │  │ │  │       INTERSECT = 中間重疊
 │  └─┼──┼─┘  │       A EXCEPT B = 只有 A 的部分
 └────┘  └────┘
```

## 🎯 使用規則（必考）

兩個查詢必須「**相容（union-compatible）**」：
1. **欄位數相同**
2. 對應欄位的**資料型態相容**

結果的欄位名稱以**第一個查詢**為準。
`ORDER BY` 只能寫在**最後面**，作用於整個結果。

```sql
SELECT question_id FROM practice_log
UNION
SELECT question_id FROM question_topics WHERE topic_id = 1
ORDER BY question_id;
```

## UNION vs UNION ALL

| | UNION | UNION ALL |
|---|---|---|
| 重複資料 | 去除 | 保留 |
| 效能 | 較慢（要比對去重） | **較快** |

💼 **工作原則**：確定不會重複，或重複也沒關係時，用 **UNION ALL**。

## 💼 常見用途

- 合併結構相同的多張表：例如 `orders_2024 UNION ALL orders_2025`
- 把多個統計結果放在同一張報表：
  ```sql
  SELECT '總題數', COUNT(*) FROM questions
  UNION ALL
  SELECT '作答次數', COUNT(*) FROM practice_log;
  ```
- 比對兩份名單：用 EXCEPT 找出「A 有、B 沒有」的資料

## 🎯 和關聯代數的關係

- 聯集 ∪、交集 ∩、差集 − 都是關聯代數的運算
- 交集可以用差集表示：**A ∩ B = A − (A − B)**
- 所以交集「不是」基本運算（基本運算：選擇 σ、投影 π、聯集 ∪、差集 −、笛卡兒積 ×、更名 ρ）

## 小測驗

1. 下列關於 UNION 的敘述，何者錯誤？
   (A) 兩個查詢的欄位數必須相同
   (B) UNION 會去除重複的列
   (C) UNION ALL 的效能通常比 UNION 好
   (D) 兩個查詢的欄位名稱必須相同

2. A = {1, 2, 3, 4}，B = {3, 4, 5}，A − B 的結果為？
   (A) {1, 2} (B) {5} (C) {3, 4} (D) {1, 2, 5}

<details>
<summary>看答案</summary>

1. **(D)**。欄位名稱不需相同，結果以第一個查詢的名稱為準
2. **(A)**
</details>
