# 8-2 叢集索引與非叢集索引 🎯💼

> 本課只有觀念，沒有練習檔。

## 🎯 叢集索引（Clustered Index）

**資料本身就依照索引鍵的順序存放**。索引的葉節點**就是資料本身**。

💡 **類比**：**字典**。字典本身就是依注音 / 部首排序的，找到索引位置就等於找到內容。

```
叢集索引（B+ Tree）
         [ 30 | 60 ]
        /     |     \
  ┌─────────┐ ┌─────────┐ ┌─────────┐
  │10 王小明│ │30 陳大同│ │60 林美美│   ← 葉節點就是完整的資料列
  │20 李小華│ │40 黃小玲│ │70 張志明│     而且依鍵值排序
  └─────────┘ └─────────┘ └─────────┘
```

特性：
- 一張表**只能有一個**叢集索引（資料只能有一種實體排列順序）
- **範圍查詢很快**（資料連續存放）
- 依叢集索引鍵排序的查詢不需要額外排序

## 🎯 非叢集索引（Non-clustered Index）

**索引和資料分開存放**。索引的葉節點存的是「**鍵值 + 指向資料的指標**」。

💡 **類比**：**書後面的索引頁**。索引頁依筆畫排序，但書的內容是依章節排序，
找到索引後還要「翻到第幾頁」。

```
非叢集索引（依姓名）              資料（依學號存放）
┌──────────────┐                ┌────────────┐
│ 王小明 → 第3頁│ ─────────────▶ │ 第3頁：10 王小明 │
│ 李小華 → 第3頁│ ─────────────▶ │       20 李小華 │
│ 林美美 → 第7頁│ ─────────────▶ │ 第7頁：60 林美美 │
└──────────────┘                └────────────┘
```

特性：
- 一張表可以有**多個**非叢集索引
- 找到索引後，還要**再去讀取資料**（稱為 **lookup**，多一次讀取）

## 🎯 比較（必考）

| | 叢集索引 | 非叢集索引 |
|---|---|---|
| 資料的實體順序 | **依索引鍵排序** | 與索引無關 |
| 葉節點存放 | **完整的資料** | 鍵值 + 指標 |
| 每張表數量 | **最多 1 個** | 可以多個 |
| 範圍查詢 | **很快** | 較慢（每筆都要 lookup） |
| 新增資料 | 可能要搬移資料以維持順序（頁分裂） | 較少影響資料本身 |

## 💼 各資料庫的實作

| 資料庫 | 叢集索引 |
|---|---|
| **SQL Server** | 建立 PRIMARY KEY 時**預設**建立叢集索引（可以改） |
| **MySQL InnoDB** | **主鍵一定是叢集索引**。次索引的葉節點存的是「主鍵值」，而不是實體位置 |
| **Oracle** | 一般表沒有叢集索引；要用 IOT（Index-Organized Table） |
| **PostgreSQL** | 沒有自動維護的叢集索引（`CLUSTER` 指令只做一次性排序） |
| **SQLite** | 一般表依 **rowid** 存放（rowid 就是叢集鍵）；`WITHOUT ROWID` 表則依主鍵存放 |

## 💼 涵蓋索引（Covering Index）

如果查詢需要的**所有欄位都在索引裡**，就不需要再回去讀資料（省掉 lookup），效能最好。

```sql
CREATE INDEX idx_log_q_correct ON practice_log(question_id, is_correct);

-- 這個查詢只用到 question_id 和 is_correct，索引裡都有 → 涵蓋索引
SELECT question_id, SUM(is_correct) FROM practice_log GROUP BY question_id;
```

## 💼 叢集索引鍵的選擇

叢集索引鍵最好是：
- **遞增的**（例如自動編號）：新資料加在最後面，不用搬移既有資料
- **窄的**（欄位小）：次索引會存叢集鍵（MySQL、SQL Server），鍵越大所有索引越大
- **不常變動的**：改了叢集鍵，資料要搬家

⚠️ 用 **UUID / GUID**（隨機值）當叢集主鍵，新資料會插入在隨機位置，
造成大量的頁分裂，效能很差。

   (A) 資料會依索引鍵實體排序
   (B) 一個表只能有一個
   (C) 葉節點存放指向資料的指標
