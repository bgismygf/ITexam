# 8-5 常見慢查詢寫法與改寫 💼

有索引不代表一定會用到。下面這些寫法會讓索引「**失效**」，是工作上最常見的效能問題。

## 1. ❌ 對欄位使用函數或運算

```sql
-- ❌ 索引失效：每一列都要先算 substr，才能比較
WHERE substr(answered_at, 1, 10) = '2025-03-01'
WHERE year + 1911 = 2024
WHERE UPPER(email) = 'A@B.COM'

-- ✅ 改寫：讓欄位保持「原樣」，把運算移到另一邊
WHERE answered_at >= '2025-03-01' AND answered_at < '2025-03-02'
WHERE year = 2024 - 1911
```

💡 **原則**：**索引欄位要「裸」著放在比較運算子的一邊**。
這種能用到索引的條件稱為 **SARGable**（Search ARGument able）。

## 2. ❌ LIKE 開頭是萬用字元

```sql
WHERE name LIKE '%小明'      -- ❌ 開頭不確定，無法用索引
WHERE name LIKE '%小明%'     -- ❌
WHERE name LIKE '王%'        -- ✅ 開頭確定，可以用索引
```

需要「包含」搜尋時，考慮**全文檢索**（Full-Text Search）功能。

> ⚠️ SQLite 的 LIKE 預設不分大小寫，一般索引不能直接用在 LIKE 上。
> MySQL、SQL Server 的 `LIKE '王%'` 可以正常使用索引。

## 3. ❌ 隱含型態轉換

```sql
-- phone 是文字欄位
WHERE phone = 912345678      -- ❌ 數字和文字比較，可能要逐列轉換，索引失效
WHERE phone = '0912345678'   -- ✅ 型態一致
```

## 4. ❌ OR 連接不同欄位

```sql
-- ❌ 有些資料庫無法同時用兩個索引
WHERE user_name = 'user1' OR question_id = 5

-- ✅ 改寫成 UNION
SELECT * FROM t WHERE user_name = 'user1'
UNION
SELECT * FROM t WHERE question_id = 5
```
同一欄位的 OR 改用 `IN`：`WHERE id = 1 OR id = 2` → `WHERE id IN (1, 2)`

## 5. ❌ SELECT *

- 撈出不需要的欄位，增加 I/O 和網路傳輸
- 無法使用**涵蓋索引**

✅ 只選需要的欄位。

## 6. ❌ N+1 查詢問題（程式端）

```
-- 程式先查出 100 份考試
SELECT * FROM exams;
-- 然後在迴圈中，每份考試再查一次題目 → 共 1 + 100 = 101 次查詢！
SELECT * FROM questions WHERE exam_id = 1;
SELECT * FROM questions WHERE exam_id = 2;
...
```

✅ 用一次 JOIN 或 `WHERE exam_id IN (...)` 取得全部資料。
這是使用 ORM（物件關聯對映）框架時最常見的效能問題。

## 7. ❌ 用 OFFSET 做深分頁

```sql
SELECT * FROM t ORDER BY id LIMIT 20 OFFSET 100000;   -- ❌ 要先讀過 100000 筆再丟掉
```

✅ 改用「**鍵集分頁**」（Keyset Pagination），記住上一頁最後一筆的 id：
```sql
SELECT * FROM t WHERE id > 100000 ORDER BY id LIMIT 20;
```

## 8. ❌ 不必要的 DISTINCT、ORDER BY

- `DISTINCT` 要排序或雜湊去重，如果資料本來就不會重複，就不要加
- 子查詢裡的 `ORDER BY` 通常沒有意義（外層會重新決定順序）

## 9. ⚠️ NOT IN、相關子查詢

- `NOT IN` 有 NULL 陷阱（4-2 課），效能也常不如 `NOT EXISTS`
- 相關子查詢可能每列執行一次，可改寫成 JOIN 或視窗函數

## 總整理

| 慢的寫法 | 改寫 |
|---|---|
| `WHERE func(欄位) = 值` | `WHERE 欄位 = 反運算(值)` / 範圍條件 |
| `LIKE '%xx'` | `LIKE 'xx%'` 或全文檢索 |
| 型態不一致 | 型態一致 |
| 不同欄位 `OR` | `UNION` |
| `SELECT *` | 只選需要的欄位 |
| 迴圈中查詢（N+1） | 一次 JOIN / IN |
| `OFFSET` 很大 | 鍵集分頁 |
| `NOT IN (子查詢)` | `NOT EXISTS` |

## 💼 效能調校的心態

1. **先量測，再最佳化**：用 EXPLAIN 和執行時間確認瓶頸，不要憑感覺
2. **一次只改一個地方**，改完再量測
3. 最有效的通常是：**加對索引** > **改寫 SQL** > **調整資料庫設定** > **升級硬體**
