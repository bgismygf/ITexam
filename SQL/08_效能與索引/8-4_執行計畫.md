# 8-4 讀懂執行計畫 EXPLAIN 💼

## 觀念

**執行計畫（Execution Plan）**：資料庫打算**怎麼執行**你的 SQL，
例如要不要用索引、先讀哪張表、用什麼方法 JOIN。

SQL 只描述「要什麼」，「怎麼做」由資料庫的**查詢最佳化器（Query Optimizer）**決定。
EXPLAIN 讓你看到最佳化器的決定，是**診斷慢查詢的第一步**。

## 語法

| 資料庫 | 寫法 |
|---|---|
| **SQLite** | `EXPLAIN QUERY PLAN SELECT ...` |
| **MySQL** | `EXPLAIN SELECT ...` |
| **PostgreSQL** | `EXPLAIN SELECT ...`、`EXPLAIN ANALYZE SELECT ...`（實際執行並計時） |
| **SQL Server** | SSMS 中按「顯示估計執行計畫」（Ctrl+L），或 `SET SHOWPLAN_TEXT ON` |
| **Oracle** | `EXPLAIN PLAN FOR SELECT ...` |

## SQLite 執行計畫的關鍵字

| 關鍵字 | 意思 | 好壞 |
|---|---|---|
| `SCAN 表名` | **全表掃描**，每一列都讀 | ⚠️ 大表要注意 |
| `SEARCH 表名 USING INDEX 索引名 (欄位=?)` | **用索引搜尋** | ✅ 好 |
| `SEARCH 表名 USING INTEGER PRIMARY KEY (rowid=?)` | 用主鍵搜尋 | ✅ 最好 |
| `SEARCH ... USING COVERING INDEX` | 用索引搜尋，而且是**涵蓋索引**，不用回去讀資料 | ✅✅ 非常好 |
| `SCAN 表名 USING COVERING INDEX` | 把**整個索引**從頭掃到尾（索引比資料表小，比 SCAN 整張表快一點，但仍然是掃描） | ⚠️ 條件沒有用到索引來搜尋 |
| `USE TEMP B-TREE FOR ORDER BY` | 需要**額外排序** | ⚠️ 可以考慮用索引避免 |
| `USE TEMP B-TREE FOR GROUP BY` | 需要額外排序來分組 | ⚠️ |
| `AUTOMATIC COVERING INDEX` | SQLite 臨時自動建了索引 | ⚠️ 代表這裡缺一個索引 |

## 範例

```sql
EXPLAIN QUERY PLAN
SELECT * FROM my_big_log WHERE user_name = 'user1234';
```

沒有索引：
```
SCAN my_big_log
```

建立索引後：
```
SEARCH my_big_log USING INDEX idx_big_user (user_name=?)
```

## 💼 其他資料庫的對照

| 意思 | SQLite | MySQL（type 欄位） | SQL Server |
|---|---|---|---|
| 全表掃描 | SCAN | `ALL` | Table Scan / Clustered Index Scan |
| 索引範圍掃描 | SEARCH ... (x>?) | `range` | Index Seek |
| 索引等值查詢 | SEARCH ... (x=?) | `ref` / `eq_ref` | Index Seek |
| 主鍵 / 唯一查詢 | SEARCH ... PRIMARY KEY | `const` | Clustered Index Seek |

## 判讀步驟

1. 找有沒有大表的**全表掃描**（SCAN / ALL / Table Scan）
2. 看 WHERE、JOIN 的欄位**有沒有用到索引**
3. 看有沒有**額外的排序**（TEMP B-TREE / Using filesort）
4. 修改（加索引或改寫 SQL）後，**再 EXPLAIN 一次確認**

⚠️ **小表全表掃描是正常的**：資料很少時，最佳化器會判斷全表掃描比較快。
