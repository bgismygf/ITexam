# 2-1 雲端特性與服務模式：SaaS、PaaS、IaaS 🎯💼

> 對應考古題：109（解釋名詞 PaaS）、110（雲端運算服務的 3 項類別）、112（CSP 提供之服務分為 3 個種類，請說明定義，6 分）、113（SaaS、PaaS、IaaS 各列出 2 個 CSP 實例，6 分）
> 服務定義依國家資通安全研究院《政府機關雲端服務應用資安參考指引》v1.4（114 年 12 月）整理。

## 觀念

**雲端運算**：透過網路，**依需求**取用共享的運算資源（伺服器、儲存、網路、平台、軟體），**用多少付多少**，不必自己買設備、建機房。

比喻：自己發電（自建機房） vs 向電力公司買電（使用雲端）。

### 🎯 雲端運算的五個特性（NIST 定義）

| 特性 | 說明 |
|---|---|
| **隨需自助服務**（On-demand Self-service） | 使用者自己在網頁上開通資源，不用找廠商人工處理 |
| **廣泛網路存取**（Broad Network Access） | 透過網路，用各種裝置（電腦、手機）都能存取 |
| **資源池化**（Resource Pooling） | 提供者把資源集中成資源池，由**多個租戶共享**，動態分配 |
| **快速彈性**（Rapid Elasticity） | 資源可以**快速擴充或縮減**，例如活動期間流量暴增時自動加開主機 |
| **可量測的服務**（Measured Service） | 使用量被監控和計量，**依使用量計費** |

## 🎯 三種服務模式

資通系統可以分成三層：**基礎設施**（最底層，電力、空調、網路、主機）、**平台**（中間層，作業系統、開發平台）、**軟體**（最上層，應用程式）。
三種服務模式的差別在於：**雲端服務提供者（CSP）幫你管到哪一層**。

```
                本地部署        IaaS          PaaS          SaaS
              ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐
  應用程式     │ ■ 自己   │  │ ■ 自己   │  │ ■ 自己   │  │ □ 提供者 │
  資料        │ ■ 自己   │  │ ■ 自己   │  │ ■ 自己   │  │ ■ 自己*  │
  執行環境     │ ■ 自己   │  │ ■ 自己   │  │ □ 提供者 │  │ □ 提供者 │
  作業系統     │ ■ 自己   │  │ ■ 自己   │  │ □ 提供者 │  │ □ 提供者 │
  虛擬化      │ ■ 自己   │  │ □ 提供者 │  │ □ 提供者 │  │ □ 提供者 │
  伺服器、儲存 │ ■ 自己   │  │ □ 提供者 │  │ □ 提供者 │  │ □ 提供者 │
  網路、機房   │ ■ 自己   │  │ □ 提供者 │  │ □ 提供者 │  │ □ 提供者 │
              └─────────┘  └─────────┘  └─────────┘  └─────────┘
  ■ 使用者管理   □ 雲端服務提供者管理
  * 不管哪一種模式，資料內容、帳號和存取權限都是使用者的責任（2-2 課責任共擔）
```

| 模式 | 定義（依政府指引） | 提供給誰 | 使用者負責 |
|---|---|---|---|
| **IaaS**<br>基礎設施即服務 | 提供儲存空間、網路傳輸及各種**運算資源**，使用者**無須購買**伺服器、網路設備、電力及空調等設施，也**無須控管或維護底層基礎設施** | **系統管理者** | 作業系統、中介軟體、應用程式、資料 |
| **PaaS**<br>平台即服務 | 提供**運算平台**解決方案，主要提供程式庫及程式模組等**系統開發環境**，使用者**不需管理與控制**雲端基礎設施（含網路、伺服器、作業系統或儲存空間） | **開發者** | 應用程式、資料 |
| **SaaS**<br>軟體即服務 | 「**即需即用軟體**」：提供者集中代管軟體與相關資料，使用者**只要透過網際網路瀏覽操作，不須安裝即可使用** | **一般使用者** | 資料、帳號設定 |

💡 **記法**：
- **IaaS** 給你一台「空的虛擬主機」，其他自己裝
- **PaaS** 給你一個「寫程式的環境」，只管程式和資料
- **SaaS** 給你一個「做好的軟體」，打開瀏覽器就能用

### 🎯 實例（113 年題：每種列 2 個）

| 模式 | 實例 |
|---|---|
| **SaaS** | **Gmail**、Google Workspace（Google 文件、雲端硬碟）、**Microsoft 365**（Outlook、Teams）、Salesforce、Dropbox、Apple iCloud |
| **PaaS** | **Google App Engine**、**Microsoft Azure App Service**、AWS Elastic Beanstalk、Heroku、Google Cloud Run |
| **IaaS** | **Amazon EC2**（AWS）、**Google Compute Engine**（GCP）、**Microsoft Azure Virtual Machines**、中華電信 hicloud |

⚠️ 同一家 CSP 會同時提供三種模式，作答時寫**具體的服務名稱**（例如「Amazon EC2」），不要只寫「AWS」。

### 三種模式比較

| | IaaS | PaaS | SaaS |
|---|---|---|---|
| 使用者的控制程度 | **最高** | 中 | **最低** |
| 需要的技術能力 | **最高**（要管作業系統） | 中（要會開發） | **最低**（會操作就好） |
| 彈性 | 最高 | 中 | 最低（只能用提供的功能） |
| 使用者的資安責任 | **最多** | 中 | **最少** |
| 適合 | 要把現有系統搬上雲（直接搬移）、需要特殊環境 | 開發新的應用程式 | 一般辦公、標準化業務 |

### 其他「XaaS」

| 名稱 | 意思 |
|---|---|
| **FaaS**（Function as a Service）／無伺服器運算 | 只上傳函式，有事件時才執行，依執行次數計費（例如 AWS Lambda） |
| **DaaS**（Desktop as a Service） | 雲端桌面 |
| **SECaaS**（Security as a Service） | 雲端資安服務，例如雲端 WAF、雲端郵件過濾 |

### 雲端的優點與風險

| 優點 | 風險 |
|---|---|
| 不用一次投入大量設備成本（資本支出變營運支出） | **資料放在別人那裡**，有外洩和法規風險 |
| 快速擴充，彈性高 | **錯誤設定**是最常見的雲端資安事件原因 |
| 大型 CSP 的資安和可用性投資，通常比單一機關自建更多 | 依賴網路；被**單一廠商綁定**（Vendor Lock-in） |
| 減少機房管理人力 | 費用沒控管好可能超支 |

## 💼 工作實作

- **你每天都在用 SaaS**：公司的 Microsoft 365 或 Google Workspace 信箱、線上會議都是 SaaS
- **評估上雲時先問**：這個系統的資料等級是什麼？可以放在公有雲嗎？要用哪種服務模式？（2-2 課的政府指引規定）
- **雲端費用管理**：IaaS 的主機不用時要關機或縮小規格，否則會一直計費。設定**預算警示**是基本功
- **錯誤設定最危險**：例如雲端儲存空間（如 AWS S3）設成「公開」，資料就會被任何人下載，是常見的外洩原因

## 📝 考古題示範

### 112 年（一）：雲端服務提供者（CSP）提供之服務分為 3 個種類，請說明定義（6 分）

> 參考答案（依政府機關雲端服務應用資安參考指引整理，不是官方公布的答案）

1. **基礎設施即服務（IaaS）**：提供儲存空間、網路傳輸及各種運算資源，使用者無須購買伺服器、網路設備、電力與空調等設施，也無須控管或維護底層基礎設施，但須自行管理作業系統與應用程式。
2. **平台即服務（PaaS）**：提供運算平台解決方案，主要提供程式庫及程式模組等系統開發環境，使用者不需管理與控制網路、伺服器、作業系統或儲存空間等雲端基礎設施，只需專注於應用程式開發。
3. **軟體即服務（SaaS）**：「即需即用軟體」，由雲端服務提供者集中代管軟體與相關資料，使用者僅需透過網際網路瀏覽操作，不須安裝即可使用。

### 113 年（一）：針對 SaaS、PaaS、IaaS，分別列出 2 個 CSP 實例（6 分）

> 參考答案（自己寫的，不是官方答案）

1. **SaaS**：Google 的 Gmail、Microsoft 的 Microsoft 365
2. **PaaS**：Google 的 App Engine、Microsoft 的 Azure App Service
3. **IaaS**：Amazon 的 EC2、Google 的 Compute Engine
