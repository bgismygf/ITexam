## 🎯 巨量資料的特性（V）

| V | 意思 | 例子 |
|---|---|---|
| **Volume**（資料量大） | 資料量從 TB 到 PB 以上，傳統資料庫難以處理 | 全台數百萬戶智慧電表每 15 分鐘一筆讀值 |
| **Velocity**（速度快） | 資料**產生和需要處理的速度**很快，常要**即時**處理 | 感測器串流資料、網站點擊流 |
| **Variety**（種類多） | **結構化**、**半結構化**、**非結構化**資料並存 | 資料表、JSON、日誌、影像、社群貼文 |
| **Veracity**（真實性） | 資料品質參差，可能有雜訊、錯誤、偏誤，要判斷可信度 | 感測器故障送出異常值 |
| **Value**（價值） | 從大量資料中**萃取出有用的價值**，但價值密度低 | 從用電資料找出竊電行為 |

💡 最早是 **3V**（Volume、Velocity、Variety），後來加上 Veracity 成為 **4V**，再加上 Value 成為 **5V**。題目問幾個 V 就寫幾個，寫最前面的幾個。

### 資料的三種結構

| 類型 | 說明 | 例子 |
|---|---|---|
| **結構化** | 有固定欄位，可以放進資料表 | 訂單、帳務資料 |
| **半結構化** | 有標籤或結構，但不固定 | JSON、XML、日誌檔 |
| **非結構化** | 沒有固定結構 | 文件、影像、影片、語音、社群貼文 |

## 🎯 Hadoop

**Hadoop**：Apache 的**開源**大數據處理框架，用**大量便宜的一般電腦組成叢集**，**分散儲存**和**平行處理**巨量資料。

核心：「**把運算搬到資料旁邊**」，不是把大量資料搬來搬去。

### 🎯 HDFS（Hadoop 分散式檔案系統）

| 元件 | 角色 |
|---|---|
| **NameNode**（主節點） | 管理**詮釋資料**：檔案名稱、每個區塊存在哪些 DataNode |
| **DataNode**（工作節點） | 實際**儲存資料區塊** |

運作方式：
- 大檔案切成固定大小的**區塊**（Block，預設 128 MB），分散存在多台 DataNode
- 每個區塊**預設複製 3 份**，存在不同機器上，**某台壞掉資料也不會遺失**（容錯）
- 適合「**寫一次、讀很多次**」的大檔案

### 🎯 MapReduce

**平行處理**大量資料的程式模型，分成兩個階段：

| 階段 | 做什麼 |
|---|---|
| **Map**（映射） | 把資料切成多份，**各節點平行處理**，輸出成 (鍵, 值) 配對 |
| **Shuffle**（洗牌） | 把**相同的鍵**送到同一個節點 |
| **Reduce**（歸納） | 對同一個鍵的所有值做彙總，輸出最終結果 |

例：計算大量文件中每個字出現的次數（Word Count）

```
輸入：            Map：                Shuffle：           Reduce：
「電 費 電」  →   (電,1)(費,1)(電,1)    (電,[1,1,1])   →    (電,3)
「費 表 電」  →   (費,1)(表,1)(電,1) →  (費,[1,1])     →    (費,2)
                                       (表,[1])       →    (表,1)
```

### Hadoop 生態系

| 元件 | 用途 |
|---|---|
| **YARN** | 管理叢集的運算資源，分配給各個工作 |
| **Hive** | 用類似 **SQL** 的語法查詢 HDFS 上的資料 |
| **HBase** | 建在 HDFS 上的**欄族型 NoSQL** 資料庫 |
| **Spark** | **記憶體內運算**，比 MapReduce 快很多，支援串流、機器學習、SQL |
| **Kafka** | 處理大量**即時串流**資料的訊息平台 |

### MapReduce vs Spark

| | MapReduce | Spark |
|---|---|---|
| 中間結果 | 寫到**硬碟** | 放在**記憶體** |
| 速度 | 較慢 | **快很多**（特別是需要反覆運算的機器學習） |
| 適合 | 大量批次處理 | 批次、**即時串流**、機器學習、互動式查詢 |

## 🎯 資料湖 vs 資料倉儲

| | 資料倉儲（Data Warehouse） | 資料湖（Data Lake） |
|---|---|---|
| 存什麼 | **整理過的結構化**資料 | **原始**資料，結構化、半結構化、非結構化都有 |
| 結構 | **寫入時**就定義好（Schema-on-Write） | **讀取時**才定義（Schema-on-Read） |
| 使用者 | 業務分析人員、主管報表 | 資料科學家、機器學習 |
| 成本 | 較高 | 較低（便宜的大量儲存） |

現在常見把兩者結合的「**資料湖倉**（Lakehouse）」。

## 🎯 整合現有架構與大數據平台（107 年題）

```
┌─────────────── 資料來源 ───────────────┐
│ 既有系統：ERP、CRM、帳務 TPS（結構化）    │
│ 新型態：日誌、電子郵件、社群、感測器       │
│        （半結構化、非結構化、即時串流）     │
└───────────────────┬──────────────────┘
        批次（ETL）   │   即時串流（Kafka）
                    ▼
┌─────────────── 資料系統 ───────────────┐
│ 資料湖：HDFS／雲端物件儲存，存放原始資料   │
│ 處理：Spark、MapReduce（批次）、串流處理   │
│ 資料倉儲／MPP 資料庫：整理後的結構化資料    │
│ NoSQL：大量、高速、格式多變的資料          │
│ 資料治理：資料目錄、品質、權限（1-2 課）    │
└───────────────────┬──────────────────┘
                    ▼
┌─────────────── 資料應用 ───────────────┐
│ BI 報表與儀表板（主管決策）                │
│ 機器學習：預測、異常偵測（6-2 課）         │
│ 即時監控與告警                           │
│ 資料 API 提供給其他系統                   │
└────────────────────────────────────────┘
```

**整合規劃的重點**：
1. **不取代、而是延伸**：既有的資料倉儲繼續服務報表，新型態資料進資料湖，兩者透過 ETL 互通
2. **分流處理**：批次資料走 ETL、即時資料走串流平台
3. **成本考量**：大量歷史資料放便宜的資料湖，常用的彙總資料放資料倉儲
4. **資料治理與資安**：統一的資料目錄、權限控管和個資保護

## 💼 工作實作

- **國營事業的大數據**：智慧電表、管線感測器、設備運轉紀錄、客服紀錄都是巨量資料，可以用來做負載預測、設備預防保養、異常用電偵測
- **大數據不一定要自己建 Hadoop**：現在多半用雲端服務（例如 Google BigQuery、AWS EMR、Azure Synapse），或依資料量選擇合適的工具。資料量沒有大到單一資料庫處理不了，就不需要大數據平台
- **資料品質比資料量重要**：Veracity 不好，分析結果就不可信。分析前先做資料清理（SQL 10-2 課）

### 106 年：巨量資料特性；Hadoop 架構與 HDFS、MapReduce 的功能

> 參考答案（自己寫的，不是官方答案）

**（一）巨量資料特性**
1. **Volume（大量）**：資料量龐大，從 TB 到 PB 以上
2. **Velocity（快速）**：資料產生與處理速度快，常需即時處理
3. **Variety（多樣）**：包含結構化、半結構化與非結構化資料
4. **Veracity（真實性）**：資料品質不一，須判斷其可信度
（若題目要 5V，再加上 **Value（價值）**：從大量資料中萃取有用價值）

**（二）Hadoop 架構**

Hadoop 是 Apache 的開源分散式運算框架，以大量一般電腦組成叢集，分散儲存與平行處理巨量資料，核心為：
1. **HDFS（分散式檔案系統）**：將大檔案切成區塊分散儲存於多台 DataNode，並預設複製 3 份以達到容錯；由 NameNode 管理檔案與區塊位置等詮釋資料
2. **MapReduce（平行運算模型）**：Map 階段將資料分散到各節點平行處理並輸出鍵值對，經 Shuffle 將相同鍵彙集後，由 Reduce 階段彙總產生結果
