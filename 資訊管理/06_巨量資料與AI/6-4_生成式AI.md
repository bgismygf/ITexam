# 6-4 生成式 AI：提示詞工程、脈絡工程、駕馭工程 🎯💼

> 對應考古題：115（AI 開發的方法在近年經歷了 3 個階段，每階段都在解決更深層的問題：說明何謂提示詞工程、脈絡工程、駕馭工程，各 6 分）
> ⚠️ 「脈絡工程」「駕馭工程」是 2025～2026 年才流行的名詞，定義主要來自業界的技術文章，還沒有統一的標準。本課依多個來源的共同說法整理，來源列在最後。

## 觀念：生成式 AI 與大型語言模型

**生成式 AI**（Generative AI）：能**產生新內容**（文字、圖片、程式碼、語音）的 AI。

**大型語言模型**（LLM，Large Language Model）：用海量文字訓練的生成式 AI，例如 ChatGPT、Claude、Gemini。

| 名詞 | 意思 |
|---|---|
| **Token**（詞元） | 模型處理文字的單位，大約是一個字或半個詞。使用量和費用都用 token 計算 |
| **預訓練** | 用大量文字讓模型學會「預測下一個詞」，從中學到語言和知識 |
| **微調**（Fine-tuning） | 用特定領域的資料再訓練，讓模型適應特定任務 |
| **脈絡視窗**（Context Window） | 模型一次能「看到」的文字量上限，包括指示、文件、對話紀錄 |
| **幻覺**（Hallucination） | 模型產生**看似合理但錯誤**的內容，例如捏造不存在的法條或文獻 |
| **RAG**（檢索增強生成） | 先從資料庫**檢索相關文件**，放進脈絡，再讓模型根據文件回答，可以減少幻覺、使用最新或內部資料 |
| **AI 代理**（AI Agent） | 不只回答問題，還能**自己規劃步驟、呼叫工具**（搜尋、執行程式、查資料庫）來完成任務 |

## 🎯 AI 開發的三個階段

| 階段 | 關注的問題 | 範圍 |
|---|---|---|
| **① 提示詞工程** | 「**怎麼問**」才能得到好答案？ | 一段指示 |
| **② 脈絡工程** | 「**給模型看什麼資訊**」，它才能把事情做對？ | 模型每次看到的全部內容 |
| **③ 駕馭工程** | 「**模型外面要搭什麼系統**」，它才能可靠地完成任務？ | 模型以外的整個系統 |

後一個階段**包含**前一個階段，不是取代：

```
  ┌───────────────────── 駕馭工程（模型外的整個系統）─────────────────────┐
  │  工具與權限、流程控制、狀態與記憶、防護機制、錯誤處理、評估與監控        │
  │   ┌──────────────── 脈絡工程（模型看到的全部資訊）────────────────┐   │
  │   │  系統指示、檢索到的文件、對話紀錄、工具執行結果、記憶            │   │
  │   │   ┌──────── 提示詞工程（指示怎麼寫）────────┐                 │   │
  │   │   │  角色、任務、格式、範例                   │                 │   │
  │   │   └──────────────────────────────────────┘                 │   │
  │   └───────────────────────────────────────────────────────────┘   │
  └─────────────────────────────────────────────────────────────────┘
```

### 🎯 ① 提示詞工程（Prompt Engineering）

**定義**：設計和調整給 AI 的**指示（提示詞）**，讓模型產生更準確、更符合需求的輸出。

常用技巧：

| 技巧 | 說明 | 例子 |
|---|---|---|
| **給角色** | 指定模型扮演的身分 | 「你是資安顧問」 |
| **任務明確** | 清楚說明要做什麼、給誰看 | 「替新進員工寫一份 300 字的釣魚信辨識說明」 |
| **提供背景** | 說明情境和限制 | 「讀者沒有資訊背景」 |
| **指定格式** | 要表格、條列、JSON | 「用三欄表格：手法、特徵、防範」 |
| **給範例**（Few-shot） | 附上幾個輸入和期望輸出的範例 | 給兩個分類好的例子，再請模型分類第三個 |
| **逐步思考**（Chain of Thought） | 要求模型先列出推理步驟再回答 | 「請一步一步推導」 |

**解決的問題**：同一個模型，問法不同，答案品質差很多。
**限制**：只能調整「怎麼問」，模型**缺少的資訊**和**做不到的事**，提示詞再好也補不了。

### 🎯 ② 脈絡工程（Context Engineering）

**定義**：設計並管理模型每次執行時**脈絡視窗中的全部內容**，在正確的時間、以正確的格式，提供完成任務**所需的資訊**。

脈絡包含：

| 內容 | 說明 |
|---|---|
| 系統指示 | 角色、規則、限制（提示詞工程的成果） |
| **檢索到的資料** | 用 RAG 從內部文件、資料庫找到的相關內容 |
| 對話紀錄 | 之前說過什麼 |
| **工具執行結果** | 搜尋結果、查詢結果、程式執行結果 |
| 記憶 | 長期保存的使用者偏好、任務進度 |

**解決的問題**：模型不知道公司內部資料和最新資訊，就會亂猜（幻覺）。脈絡工程讓模型「**看得到該看的東西**」。
**要處理的取捨**：脈絡視窗有上限，資訊太多反而會干擾模型、增加成本，所以要**挑選、摘要、排序**，只放相關的內容。

### 🎯 ③ 駕馭工程（Harness Engineering）

**定義**：設計和維護包在模型外面的「**駕馭系統（Harness）**」，也就是 AI 代理中**模型以外的所有程式和機制**，讓 AI 能可靠、安全地完成多步驟任務。業界常用的公式是：

```
AI 代理 ＝ 模型 ＋ 駕馭系統（Harness）
```

駕馭系統負責：

| 功能 | 說明 |
|---|---|
| **組裝脈絡** | 每一步決定要給模型看什麼（脈絡工程是它的一部分） |
| **定義與執行工具** | 讓模型能搜尋、查資料庫、執行程式，並把結果回傳給模型 |
| **權限與防護機制** | 限制模型能做什麼（例如刪除資料前要人工確認）、過濾危險操作 |
| **流程與狀態管理** | 管理多步驟任務的進度、步驟之間的狀態和記憶 |
| **錯誤處理** | 工具失敗或結果不符時重試、修正或停止 |
| **評估與監控** | 記錄每一步、測試輸出品質、發現問題 |

**解決的問題**：模型本身只會「產生文字」，不會自己執行、不會記得進度、也不會檢查自己有沒有做錯。要讓 AI **真的完成工作**（例如自動處理客服單、寫程式並測試），需要外面的系統來駕馭它。

💡 比喻：模型是**引擎**，提示詞是**給司機的指示**，脈絡是**地圖和路況資訊**，駕馭系統是**整台車的方向盤、煞車、儀表板和安全帶**。

### 三個階段的演進

| | 提示詞工程 | 脈絡工程 | 駕馭工程 |
|---|---|---|---|
| 核心問題 | 怎麼問 | 給什麼資訊 | 搭什麼系統 |
| 典型應用 | 單次問答、寫作 | RAG 知識問答、客服機器人 | 能自主執行多步驟任務的 AI 代理 |
| 解決的問題 | 問法不好導致答案差 | 缺少資訊導致幻覺 | 模型無法可靠地執行、驗證、恢復 |

## 生成式 AI 的風險

| 風險 | 說明 | 防範 |
|---|---|---|
| **幻覺** | 產生錯誤內容 | 用 RAG 提供依據、要求附來源、人工查證 |
| **資料外洩** | 把機敏資料貼進外部 AI 服務 | 依機關規範使用、內部部署的模型 |
| **提示詞注入**（Prompt Injection） | 攻擊者在文件或網頁中藏入指示，讓 AI 做出不該做的事 | 駕馭系統限制權限、重要操作要人工確認、區分「資料」和「指令」 |
| **偏誤與著作權** | 見 1-4 課 | |

提示詞注入是生成式 AI 特有的資安風險，概念類似 SQL Injection（5-3 課）：都是**把資料當成指令執行**。

## 💼 工作實作

- **政府機關有生成式 AI 的使用規範**：行政院訂有公部門使用生成式 AI 的參考指引，國營事業也多半有內部規定。基本原則是**不輸入機密和個資**、**產出要人工查證**、**使用者要負最終責任**
- **用 AI 寫公文、報告時**：給清楚的角色、任務、格式（提示詞工程）；附上相關的法規或前例（脈絡工程）；產出一定要自己核對內容和數字
- **評估 AI 導入專案時**：問清楚模型怎麼取得內部資料（RAG？）、能呼叫哪些工具、有什麼權限限制和人工確認機制、怎麼評估和監控品質，這些都是駕馭工程的範圍

## 📝 考古題示範

### 115 年：說明何謂提示詞工程、脈絡工程、駕馭工程（每題 6 分）

> 參考答案（自己寫的，不是官方答案）

**（一）提示詞工程（Prompt Engineering）**

提示詞工程是設計與調整輸入給 AI 模型的指示，以取得更準確、符合需求的輸出。常用技巧包括指定角色、明確描述任務與背景、規定輸出格式、提供範例（Few-shot）及要求逐步推理（Chain of Thought）。它解決「問法不當導致答案品質不佳」的問題，但無法補足模型缺乏的資訊。

**（二）脈絡工程（Context Engineering）**

脈絡工程是設計與管理模型每次執行時脈絡視窗內的全部內容，在正確時機以適當格式提供完成任務所需的資訊，包括系統指示、以 RAG 檢索的內部文件、對話紀錄、工具執行結果與記憶。它解決模型缺乏資訊而產生幻覺的問題，並須在脈絡視窗容量限制下挑選、摘要與排序資訊。提示詞工程是脈絡工程的一部分。

**（三）駕馭工程（Harness Engineering）**

駕馭工程是設計與維護包覆在模型外的駕馭系統，即 AI 代理中模型以外的所有程式與機制（AI 代理 ＝ 模型 ＋ 駕馭系統）。它負責組裝脈絡、定義與執行工具、設定權限與防護機制、管理多步驟流程與狀態、處理錯誤與重試，以及評估與監控輸出品質。它解決模型本身無法可靠執行、驗證與恢復多步驟任務的問題，脈絡工程是其中的一部分。
