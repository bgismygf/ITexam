# 4-2 資訊安全管理系統：ISO 27001、風險管理、營運持續 🎯💼

> 對應考古題：106（ISO 27001 用來持續改進 ISMS 的管理模型及具體工作項目）、113（繪圖說明 ISMS 的 PDCA 循環，12 分）

## 觀念

4-1 課講的是「**用什麼技術**保護」，這一課講的是「**怎麼管理**資安」。
買了防火牆、裝了防毒軟體，如果沒有人定期檢查、沒有人負責、出事不知道找誰，資安還是做不好。

**資訊安全管理系統（ISMS，Information Security Management System）**：
用一套**有制度、可稽核、持續改進**的方法來管理資訊安全，包括政策、組織、程序、責任和資源。

## 🎯 ISO/IEC 27001

**ISO/IEC 27001** 是國際上最普遍採用的 ISMS 標準，企業可以請第三方驗證機構稽核，通過後取得**驗證證書**。

| 版本 | 附錄 A 控制措施 |
|---|---|
| ISO/IEC 27001:2013 | 114 項，分成 14 個領域 |
| **ISO/IEC 27001:2022**（現行版） | **93 項**，分成 **4 大主題**：組織 37 項、人員 8 項、實體 14 項、技術 34 項 |

標準本文（第 4～10 章）是 ISMS 的**管理要求**，附錄 A 是可以選用的**控制措施清單**：

| 章 | 內容 | 對應 PDCA |
|---|---|---|
| 4 | 組織全景：了解組織和利害關係人、決定 ISMS 範圍 | Plan |
| 5 | 領導：高階主管的承諾、資安政策、角色與責任 | Plan |
| 6 | 規劃：**風險評鑑**與**風險處理**、資安目標 | Plan |
| 7 | 支援：資源、能力、認知（教育訓練）、溝通、文件化資訊 | Do |
| 8 | 運作：執行風險評鑑和風險處理計畫 | Do |
| 9 | 績效評估：監督量測、**內部稽核**、**管理審查** | Check |
| 10 | 改善：不符合事項與**矯正措施**、持續改善 | Act |

## 🎯 PDCA 循環（必考，要會畫）

PDCA 是 ISMS **持續改進**的管理模型，由四個階段不斷循環：

```
                ┌──────────────────────────┐
                │      P  規劃（Plan）       │
                │      建立 ISMS            │
                │ 範圍、政策、風險評鑑、       │
                │ 選擇控制措施、適用性聲明     │
                └────────────┬─────────────┘
                             │
  ┌──────────────────────┐   ▼   ┌──────────────────────┐
  │   A  行動（Act）       │       │    D  執行（Do）       │
  │   維持與改進 ISMS      │       │    實施與運作 ISMS     │
  │ 矯正措施、持續改善、     │       │ 執行風險處理計畫、      │
  │ 溝通改進結果           │       │ 實施控制措施、教育訓練   │
  └──────────▲───────────┘       └───────────┬──────────┘
             │                               │
             │  ┌─────────────────────────┐  │
             └──│     C  檢查（Check）      │◄─┘
                │     監控與審查 ISMS       │
                │ 內部稽核、管理審查、       │
                │ 量測控制措施的有效性       │
                └─────────────────────────┘

    輸入：利害關係人的資安要求和期望
    輸出：受管理的資訊安全（滿足要求和期望）
```

### 各階段的具體工作項目（106 年題）

| 階段 | 目的 | 具體工作項目 |
|---|---|---|
| **P 規劃**（Plan） | **建立** ISMS | ① 界定 ISMS 範圍 ② 訂定資安政策與目標 ③ 盤點資訊資產 ④ 執行**風險評鑑**（找出威脅、弱點、評估風險）⑤ 選擇控制措施，產出**適用性聲明（SoA）**與**風險處理計畫** ⑥ 高階主管核准 |
| **D 執行**（Do） | **實施與運作** ISMS | ① 執行風險處理計畫 ② 實施所選的控制措施 ③ 辦理教育訓練與資安認知宣導 ④ 配置資源與權責 ⑤ 建立資安事件的偵測與應變程序 |
| **C 檢查**（Check） | **監控與審查** ISMS | ① 監控和量測控制措施的有效性 ② 定期重新評估風險 ③ 執行**內部稽核** ④ 召開**管理審查**會議 ⑤ 記錄影響 ISMS 的事件 |
| **A 行動**（Act） | **維持與改進** ISMS | ① 針對稽核發現的不符合事項執行**矯正措施** ② 實施已找出的改進 ③ 將改進結果與利害關係人溝通 ④ 確認改進達到目標，再回到 Plan 進入下一輪 |

💡 **記法**：先**計畫**、再**做**、做完**檢查**、檢查完**改進**，然後繼續下一輪，所以叫「持續改進」。

⚠️ ISO 27001 從 2013 版起，標準本文不再直接寫「PDCA」，但各章的架構仍然對應 PDCA，考題也仍然這樣問。

## 🎯 風險管理

### 風險的組成

```
風險 ＝ 威脅 × 弱點 × 資產價值        （另一種寫法：風險 ＝ 發生可能性 × 衝擊程度）
```

| 名詞 | 意思 | 例子 |
|---|---|---|
| **資產**（Asset） | 對組織有價值、需要保護的東西 | 客戶資料庫、伺服器、員工 |
| **威脅**（Threat） | 可能造成傷害的**外在**事件或來源 | 駭客、勒索軟體、地震、員工誤刪 |
| **弱點**（Vulnerability） | 資產**本身**可以被利用的缺陷 | 未修補的系統漏洞、弱密碼、機房沒有門禁 |
| **風險**（Risk） | 威脅利用弱點，對資產造成損害的**可能性和影響** | 駭客利用未修補漏洞竊取客戶資料 |

💡 **威脅**是外在的，通常無法消除；**弱點**是自己的，可以修補。降低風險通常從減少弱點下手。

### 風險管理流程

```
資產盤點 → 風險識別（威脅、弱點）→ 風險分析（可能性、衝擊）→ 風險評估（排序、是否可接受）
         → 風險處理 → 監控與審查 → （回到資產盤點，持續循環）
```

### 🎯 四種風險處理方式

| 方式 | 意思 | 例子 |
|---|---|---|
| **降低**（Modify／Reduce） | 實施控制措施，降低可能性或衝擊 | 修補漏洞、加裝防火牆、啟用多因子認證 |
| **移轉**（Share／Transfer） | 把風險轉給第三方承擔 | 投保資安保險、委外給專業廠商並在合約中約定責任 |
| **避免**（Avoid） | 停止會帶來風險的活動 | 不再提供某項高風險的線上服務 |
| **接受**（Retain／Accept） | 風險在可接受範圍內，不另外處理 | 處理成本高於可能損失的低風險項目 |

處理後仍然存在的風險稱為**殘餘風險**（Residual Risk），要由管理階層正式**核准接受**。

## 🎯 營運持續與災難復原

| 名詞 | 意思 |
|---|---|
| **營運持續計畫**（BCP，Business Continuity Plan） | 發生重大事件時，讓**整個組織的關鍵業務**能持續運作的計畫（範圍較大） |
| **災難復原計畫**（DRP，Disaster Recovery Plan） | 讓**資訊系統**在災難後恢復運作的計畫（BCP 的一部分） |
| **營運衝擊分析**（BIA，Business Impact Analysis） | 分析每項業務中斷會造成多大損失，決定復原的優先順序 |

### 兩個關鍵指標

```
       最後一次備份          災難發生             系統恢復
──────────●──────────────────●──────────────────●──────────▶ 時間
          │◄──── RPO ───────►│◄───── RTO ──────►│
          │ 最多會遺失多少資料   │ 系統最多停多久     │
```

| 指標 | 全名 | 意思 | 例子 |
|---|---|---|---|
| **RTO** | 復原時間目標（Recovery Time Objective） | 系統**最多可以停多久**，必須在這段時間內恢復 | 網路銀行 RTO = 1 小時 |
| **RPO** | 復原點目標（Recovery Point Objective） | **最多可以遺失多久的資料**，決定備份頻率 | RPO = 15 分鐘，就至少每 15 分鐘備份或同步一次 |

RTO、RPO 越短，成本越高。

### 異地備援站

| 種類 | 狀態 | 復原速度 | 成本 |
|---|---|---|---|
| **熱備援站**（Hot Site） | 設備、軟體、資料都已備妥並持續同步 | **最快**（分鐘～小時） | 最高 |
| **溫備援站**（Warm Site） | 有設備和網路，資料要再還原 | 中等（小時～天） | 中 |
| **冷備援站**（Cold Site） | 只有場地、電力、空調，設備要再搬進去 | **最慢**（天～週） | 最低 |

### 備份的 3-2-1 原則

- **3** 份資料（1 份正本＋2 份備份）
- **2** 種不同的儲存媒體
- **1** 份放在**異地**

因應勒索軟體，現在常再加上「**1 份離線或不可竄改**的備份」，並**定期演練還原**（備份不能還原等於沒備份）。

## 💼 工作實作

- **國營事業普遍導入 ISO 27001**：依《資通安全責任等級分級辦法》，責任等級較高的機關要導入 ISMS 並通過公正第三方驗證（4-3 課）。新進人員會參與年度**內部稽核**、**資安教育訓練**和**社交工程演練**
- **配合稽核**：稽核員會要求出示「紀錄」，例如帳號申請單、權限清查紀錄、備份還原測試紀錄。**沒有留下紀錄，就等於沒做**
- **資產盤點**：每年要更新資訊資產清冊（設備、系統、資料），標示擁有者和資產價值，是風險評鑑的起點
- **規劃系統時先問 RTO、RPO**：例如「這個系統停一天可以嗎？資料遺失一小時可以嗎？」答案決定要不要異地備援、備份多久一次，也決定預算

### 113 年：請繪圖說明 ISO 27001 資訊安全管理系統（ISMS）的 PDCA 循環（12 分）

> 參考答案（自己寫的，不是官方答案）

1. **畫圖**：畫出上面的 PDCA 循環圖，四個階段用箭頭連成環，標出輸入（利害關係人的資安要求）和輸出（受管理的資訊安全）
2. **逐一說明四個階段**：
   - **規劃（Plan）——建立 ISMS**：界定範圍、訂定資安政策、盤點資產、執行風險評鑑、選擇控制措施，產出適用性聲明與風險處理計畫
   - **執行（Do）——實施與運作 ISMS**：執行風險處理計畫、實施控制措施、辦理教育訓練、建立事件應變程序
   - **檢查（Check）——監控與審查 ISMS**：量測控制措施有效性、內部稽核、管理審查、定期重新評估風險
   - **行動（Act）——維持與改進 ISMS**：針對不符合事項採取矯正措施、實施改進，再進入下一輪循環
3. **結論**：PDCA 讓 ISMS 不是一次性的專案，而是**持續改進**的循環，能隨著新威脅和業務變化不斷調整

💡 配分 12 分的題目，圖和文字說明都要有；只畫圖或只寫文字都會被扣分。
