# 4-4 密碼學基礎：加密、雜湊、數位簽章、PKI 🎯💼

> 本課是很多考題的基礎：4-1 課的 CIA 保護技術、5-2 課的電子郵件驗證、網路概論的 HTTPS 和 DNSSEC（114 年考題）都用到這裡的觀念。

## 觀念

密碼學解決三件事：
- **別人看不懂**（機密性）→ **加密**
- **沒有被改過**（完整性）→ **雜湊**
- **真的是他發的、他賴不掉**（鑑別性、不可否認性）→ **數位簽章**

## 🎯 對稱式加密（Symmetric）

**加密和解密用同一把金鑰。**

```
明文 ──[ 金鑰 K 加密 ]──▶ 密文 ──[ 金鑰 K 解密 ]──▶ 明文
```

| 項目 | 說明 |
|---|---|
| 常見演算法 | **AES**（現行標準）、DES、3DES（已淘汰） |
| 優點 | **速度快**，適合加密大量資料 |
| 缺點 | **金鑰傳遞困難**：要先用安全的方式把金鑰交給對方；n 個人兩兩通訊需要 **n(n−1)/2** 把金鑰 |

## 🎯 非對稱式加密（Asymmetric，公開金鑰加密）

**每個人有一對金鑰：公鑰（公開給所有人）和私鑰（只有自己有）。** 用其中一把加密，只有另一把能解開。

| 用途 | 誰的哪把鑰匙加密 | 誰解密 | 達成什麼 |
|---|---|---|---|
| **加密給對方** | 用**收件者的公鑰**加密 | 收件者用**自己的私鑰**解密 | **機密性**：只有收件者看得懂 |
| **數位簽章** | 用**寄件者的私鑰**簽章 | 任何人用**寄件者的公鑰**驗證 | **鑑別性、不可否認性**：證明是寄件者發的 |

| 項目 | 說明 |
|---|---|
| 常見演算法 | **RSA**、**ECC**（橢圓曲線，金鑰較短、效能較好） |
| 優點 | 不用事先交換秘密金鑰；n 個人只需要 **n 對**金鑰 |
| 缺點 | 速度**慢**，不適合加密大量資料 |

💡 **記法**：「**加密用對方的公鑰，簽章用自己的私鑰**」。

## 🎯 數位信封（Digital Envelope）：兩者合用

對稱式快但金鑰難傳，非對稱式好傳但慢，所以實務上**兩個一起用**：

```
寄件者：
  ① 隨機產生一把對稱金鑰 K
  ② 用 K 加密內容（快）                   ──▶ 密文
  ③ 用「收件者的公鑰」加密 K（數位信封）    ──▶ 加密後的 K
收件者：
  ④ 用自己的私鑰解開，得到 K
  ⑤ 用 K 解密內容
```

**HTTPS（TLS）**就是這個原理：先用非對稱式（或金鑰交換演算法）安全地協商出一把**工作階段金鑰**，之後的資料都用對稱式加密。

## 🎯 雜湊函數（Hash）

把**任意長度**的資料，算出**固定長度**的「指紋」（雜湊值、摘要）。

| 特性 | 意思 |
|---|---|
| **單向** | 從雜湊值**推不回**原始資料 |
| **固定長度** | 不管輸入多大，SHA-256 的結果都是 256 位元 |
| **雪崩效應** | 原始資料改一個字，雜湊值就完全不同 |
| **抗碰撞** | 很難找到兩份不同資料有相同的雜湊值 |

| 演算法 | 狀態 |
|---|---|
| MD5、SHA-1 | **已不安全**（找得到碰撞），不可再用於安全用途 |
| **SHA-256**、SHA-3 | 現行常用 |

用途：檔案**完整性**檢查、**密碼儲存**、數位簽章的前置步驟。

⚠️ **雜湊不是加密**：加密可以解密回來，雜湊不行。

### 密碼要怎麼存？

| 做法 | 安全嗎 |
|---|---|
| 存明文 | ❌ 資料庫外洩就全部曝光 |
| 用 AES 加密後存 | ❌ 金鑰外洩就能全部解開 |
| 用 SHA-256 雜湊後存 | ⚠️ 不夠：可以用預先算好的「彩虹表」反查常見密碼 |
| **加鹽（Salt）＋慢速雜湊**（bcrypt、Argon2、PBKDF2） | ✅ 每個帳號加上不同的隨機值，而且故意算得很慢，讓暴力破解不划算 |

## 🎯 數位簽章（Digital Signature）

```
寄件者：
  ① 對文件算雜湊值 H
  ② 用「寄件者的私鑰」加密 H ──▶ 數位簽章
  ③ 把「文件＋數位簽章」一起送出

收件者：
  ④ 對收到的文件自己算雜湊值 H1
  ⑤ 用「寄件者的公鑰」解開簽章，得到 H
  ⑥ 比較 H1 和 H：相同 → 文件沒被改過，而且確實是寄件者簽的
```

數位簽章同時達成：
- **完整性**：文件被改，雜湊值就對不上
- **鑑別性**：只有寄件者的公鑰解得開，證明是他簽的
- **不可否認性**：只有寄件者有私鑰，他無法否認

⚠️ 數位簽章**不提供機密性**：文件本身沒有加密，要保密還要另外加密。

## 🎯 PKI 與數位憑證

**問題**：你怎麼確定拿到的「公鑰」真的是對方的，而不是駭客假冒的？

**公開金鑰基礎建設（PKI，Public Key Infrastructure）**：由可信任的第三方**憑證機構（CA）**替公鑰「背書」。

| 元件 | 角色 |
|---|---|
| **憑證機構**（CA，Certificate Authority） | 簽發數位憑證，用 CA 自己的私鑰簽章 |
| **註冊機構**（RA，Registration Authority） | 審核申請者的身分 |
| **數位憑證**（X.509 格式） | 內容包括：持有者名稱、**持有者的公鑰**、有效期限、簽發的 CA、**CA 的數位簽章** |
| **憑證廢止**（CRL、OCSP） | 私鑰外洩或資料錯誤時，查詢憑證是否已被撤銷 |

驗證流程：瀏覽器內建信任的**根憑證**，用 CA 的公鑰驗證網站憑證上的簽章，確認憑證可信後，才使用憑證裡的公鑰。

台灣常見的例子：**自然人憑證**（內政部憑證管理中心）、**工商憑證**（經濟部）、**政府伺服器數位憑證**（GCA）。

## 💼 工作實作

### 驗證下載檔案的完整性

很多軟體官網會公布檔案的 SHA-256 值，下載後自己算一次比對：

```
certutil -hashfile 檔案名稱 SHA256      ← Windows
sha256sum 檔案名稱                       ← Linux、macOS
```

結果和官網公布的一樣，才代表檔案沒有被竄改。

### 看網站的憑證

在瀏覽器網址列點**鎖頭圖示** → 查看憑證，可以看到：簽發給誰、哪個 CA 簽發、有效期限。
憑證過期、網域不符、不是受信任的 CA 簽發，瀏覽器就會出現警告，**不要按「繼續前往」**。

### 開發時的原則

- **不要自己發明加密演算法**，使用程式語言或框架內建的成熟函式庫
- 密碼用 **bcrypt 或 Argon2** 儲存，不要用 MD5、SHA-1
- 金鑰和密碼**不要寫死在程式碼裡**，也不要上傳到 Git（3-4 課），應該放在環境變數或金鑰管理服務

## 小測驗

1. A 要傳一份機密文件給 B，只希望 B 能看懂，A 應該用哪一把金鑰加密？
   (A) A 的公鑰 (B) A 的私鑰 (C) B 的公鑰 (D) B 的私鑰

2. 數位簽章是用哪一把金鑰產生的？
   (A) 寄件者的公鑰 (B) 寄件者的私鑰 (C) 收件者的公鑰 (D) 收件者的私鑰

3. 下列何者「不是」數位簽章能提供的安全特性？
   (A) 完整性 (B) 鑑別性 (C) 不可否認性 (D) 機密性

4. 10 個人要兩兩之間用對稱式加密安全通訊，最少需要幾把金鑰？
   (A) 10 (B) 20 (C) 45 (D) 90

5. 關於雜湊函數，下列敘述何者錯誤？
   (A) 輸出長度固定 (B) 可以由雜湊值還原原始資料 (C) 原始資料稍有改變，雜湊值就差很多 (D) 可用於檢查檔案完整性

6. 儲存使用者密碼，下列哪一種做法最安全？
   (A) 明文儲存 (B) 用 AES 加密 (C) 用 MD5 雜湊 (D) 加鹽後用 bcrypt 雜湊

2. **(B)**
3. **(D)**。文件本身沒有加密

5. **(B)**。雜湊是單向的
