# 3-4 版本控制 Git 與 CI/CD 🎯💼

> 對應考古題：108（GitHub 被併購，Git 是一種開源軟體，請說明 Git 最主要之功能）
> 相關：5-4 課的 SSDLC 要求「維運階段應執行版本控制與變更管理」。

## 觀念

沒有版本控制時，大家這樣管理檔案：

```
報告.docx、報告_v2.docx、報告_最終版.docx、報告_最終版_真的最終.docx、報告_最終版_主管改過.docx
```

問題：不知道哪個是最新版、誰改了什麼、改壞了回不去、兩個人同時改會互相覆蓋。

**版本控制系統（VCS）**：記錄檔案的**每一次變更**（誰、什麼時候、改了什麼、為什麼），可以隨時**回到任何一個版本**，並讓多人**同時協作**。

## 🎯 集中式 vs 分散式

| | 集中式（例如 SVN） | **分散式**（例如 **Git**） |
|---|---|---|
| 版本歷史存在哪裡 | **只有中央伺服器**有完整歷史 | **每個人的電腦**都有完整的歷史複本 |
| 離線能不能工作 | 不行，提交要連伺服器 | **可以**，在本機提交，之後再同步 |
| 伺服器壞掉 | 歷史可能遺失 | 任何一份複本都能還原 |
| 分支 | 比較笨重 | **輕量、快速**，鼓勵多開分支 |

## 🎯 Git 的主要功能（108 年題）

**Git** 是由 Linus Torvalds（Linux 作者）在 2005 年開發的**開源、分散式版本控制系統**。主要功能：

| 功能 | 說明 |
|---|---|
| **① 記錄版本歷史** | 每次**提交（commit）**都是一個快照，記錄作者、時間、說明和變更內容 |
| **② 回復到任何版本** | 改壞了可以比較差異、還原到之前的任一版本 |
| **③ 分支與合併** | 開**分支（branch）**開發新功能，不影響主線；完成後**合併（merge）**回主線 |
| **④ 多人協作** | 每個人在自己的電腦工作，透過**遠端儲存庫**同步；同時修改同一處時會提示**衝突**，由人決定保留哪個 |
| **⑤ 追溯責任** | 查出每一行程式是誰、在哪次提交中修改的（`git blame`），方便除錯和稽核 |

### Git 和 GitHub 的差別

| | Git | GitHub |
|---|---|---|
| 是什麼 | **版本控制軟體**，裝在自己的電腦 | **代管 Git 儲存庫的網路平台** |
| 功能 | 記錄版本、分支、合併 | 遠端儲存庫、**Pull Request**（程式碼審查）、議題追蹤、CI/CD（GitHub Actions） |
| 類似服務 | | GitLab、Bitbucket、Azure DevOps |

108 年題目提到的併購，是指 **Microsoft** 在 2018 年收購 GitHub。

### Git 的三個區域

```
  工作目錄          暫存區（Staging）        本地儲存庫           遠端儲存庫
（正在改的檔案）  ──git add──▶  （準備提交的）──git commit──▶（版本歷史）──git push──▶（GitHub 等）
                                                          ◀──git pull──
```

### 常用指令

| 指令 | 作用 |
|---|---|
| `git clone 網址` | 從遠端複製整個儲存庫到本機 |
| `git status` | 看哪些檔案被修改了 |
| `git add 檔案` | 把修改加入暫存區 |
| `git commit -m "說明"` | 提交成一個新版本 |
| `git log` | 查看版本歷史 |
| `git diff` | 比較修改的內容 |
| `git branch 名稱`、`git switch 名稱` | 建立、切換分支 |
| `git merge 分支` | 把分支合併進目前的分支 |
| `git push`、`git pull` | 上傳到遠端、從遠端下載並合併 |

## 🎯 CI/CD

| 名詞 | 全名 | 意思 |
|---|---|---|
| **CI** | 持續整合（Continuous Integration） | 開發人員**頻繁**把程式合併到主線，每次合併都**自動建置和執行測試**（3-3 課的單元測試、回歸測試），及早發現問題 |
| **CD** | 持續交付（Continuous Delivery） | 通過測試的程式**隨時可以部署**，但上正式環境要**人工核准** |
| **CD** | 持續部署（Continuous Deployment） | 通過測試後**自動部署**到正式環境，不需人工介入 |

```
  提交程式 ─▶ 自動建置 ─▶ 自動測試 ─▶ 安全掃描 ─▶ 部署到測試環境 ─▶（核准）─▶ 部署到正式環境
  └──────────────── CI ────────────────┘└──────────── CD ────────────────────┘
```

把**源碼掃描、弱點掃描**（5-4 課）放進 CI/CD 流程，每次修改都自動檢查，稱為 **DevSecOps**。

## 💼 工作實作

- **委外系統也要求版本控制**：驗收時要求廠商交付完整的原始碼儲存庫（含版本歷史），不是只交一包壓縮檔，日後換廠商維護才接得下去
- **變更管理**：正式環境的每次修改都要有**變更申請、審核、測試紀錄**，對應到 Git 的提交和 Pull Request，是 ISO 27001 稽核（4-2 課）的檢查項目
- **不要把密碼、金鑰提交到 Git**：一旦提交，就算之後刪除，版本歷史裡還是找得到。用 `.gitignore` 排除設定檔，密碼放在環境變數
- **提交說明要寫清楚**：「修正」沒有意義，「修正電費試算在跨月時少算一天的錯誤」才有用
- **自己練習**：把自己的讀書筆記放進 Git 管理（這份教材就是用 Git 管理的），實際操作 `add`、`commit`、`push`

## 📝 考古題示範

### 108 年：GitHub 最近被併購，Git 是一種開源軟體，請說明 Git 最主要之功能

> 參考答案（自己寫的，不是官方答案）

Git 是一套開源的**分散式版本控制系統**，最主要的功能是**管理檔案（特別是程式原始碼）的版本變更**，支援多人協作開發。具體功能包括：
1. **版本記錄**：每次提交都保存完整快照，記錄作者、時間與修改說明
2. **版本回復**：可比較各版本差異，並還原到任一歷史版本
3. **分支與合併**：可開分支獨立開發新功能，完成後再合併回主線，不影響穩定版本
4. **分散式協作**：每位開發者本機都有完整的儲存庫，可離線工作，再透過遠端儲存庫（如 GitHub）同步，並處理修改衝突
5. **追溯責任**：可查出每一行程式由誰在何時修改，便於除錯與稽核

GitHub 則是代管 Git 儲存庫的雲端平台，另外提供程式碼審查（Pull Request）、議題追蹤與 CI/CD 等協作功能。
